## 三项工程前置

1. **隐式分组与产品集合**：[`source-inputs.gradle`](../../../build-logic/source-inputs.gradle) 提供 `dshaImplicitGroupPaths` / `dshaImplicitGroupViolations`；[`verify.gradle`](../../../build-logic/verify.gradle) 在真实源码审计之前判定：仅“已声明模块路径的严格前缀 + 无构建脚本 + 无 `src/` + 无 `sourceSets`/Android 扩展 + 无编译或 Test 任务 + 无依赖 + 无约定”的空分组被排除出产品集合，其余前缀工程按判据点名拒绝。产品集合仍须与布局完全相等。
2. **生产项目依赖白名单**：同一任务按可声明配置证明真实 Gradle 工程边，当前只允许 `:app->:core:policy`；未声明边与缺失边都失败。AGP 在可解析测试 classpath 配置里注入的模块自引用边不当作生产依赖。
3. **policy Android/反射禁止门禁**：[`test-core-boundaries.py`](../../../tools/test-core-boundaries.py) 扫描全部 `kind=jvm` 模块的生产源（去注释后），拒绝 `android./androidx.` import 与 `java.lang.reflect`/`Class.forName`/`getDeclared*`；模式本身另有正负样本。

[`test-source-layout.py`](../../../tools/test-source-layout.py) 从“单 app 等价”升级为全模块库存：
Git 跟踪源文件集合必须与布局 inventory 相等，任何声明模块之外的 `<module>/src/<set>/{java,kotlin}`
树都会失败（`tools/` 下的工程夹具与历史快照显式排除）；原缺失/重复/link/未声明源集负控全部保留，
另加未登记模块树的精确反例。[`test-build-conventions.py`](../../../tools/test-build-conventions.py)
新增静态契约要求与四条文本负控（删掉分组/源码/任务/依赖判据必须失败）。
