# DSHA 0.2.1-rc.5-20261106.0230-dsh0.2.2-rc.1 / build330

- رفض تشغيل المضيف نفسه على الشاشة الافتراضية (T76): لم يعد `/app/vscreen/launch` يقبل حزمة DSHA نفسها كهدف. لا يُنشئ النظام نسخة منفصلة للشاشة الثانوية، بل يعيد استخدام العملية نفسها قيد التشغيل؛ وWebView المرتبط مسبقًا بعرض display الافتراضي ينهار بمؤشر فارغ في `libmonochrome` على الشاشة الثانوية (دليل جهاز relay: display 4، خيط Looper الرئيسي يدخل WebView، إعادة استخدام العملية 14715 قيد التشغيل). يرفض bridge قبل أي طلب تفويض، وManager قبل claim، وCore قبل إرسال `am start`، جميعها عبر الفحص نفسه، وتعيد `VSCREEN_SELF_LAUNCH_REFUSED` (`state=NOT_SENT`، لا يُرسل أمر تشغيل ولا يحدث انهيار)؛ يصنّف الإضافة المدمجة هذا الرمز ضمن pre-dispatch، ولم يعد منتقي التطبيقات الأصلي يسرد المضيف، وتعرض صفحة النتيجة السبب بالصينية والإنجليزية. هذا رفض أمني وليس دعمًا لتشغيل المضيف على شاشة ثانوية؛ ودعمه لاحقًا يتطلب `createDisplayContext` مع نسخة WebView مستقلة. أُعيد توليد runtime-descriptor (runtimeId `6bea62f2`)؛ ولا تُعاد المدخلات الثابتة بناؤها.
- نطاق التحقق: مجموعة contracts الكاملة للمضيف، وفحص تنسيق الشجرة كاملة (JDK 17)، والاختبارات الوحدوية الموجَّهة (VirtualScreenPolicy، VirtualScreenManager ownership، صفحة التحديث)؛ لم يُجرَّ تحقق على الجهاز فعليًا. رُفع رمز الإصدار إلى 330 (أساس build329)؛ وتبقى مراجعة DSHA 0.2.1-rc.5 وDSH المضمَّن 0.2.2-rc.1.
