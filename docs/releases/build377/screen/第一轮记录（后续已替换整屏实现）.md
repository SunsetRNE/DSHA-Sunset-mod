## 主屏截图会返回哪些像素

原来用户只确认一个应用，坐标校验认识目标边界，但截图两种输出都会压缩整块显示位图。我们用一个 8×6 的显示面，在目标区填 16 个绿色像素，在目标区外填 32 个红色像素。同样的 48 个输入像素送进新旧生产截图对象，红色从 32 降到 0，绿色保持 16。几何缺失和浮层挡住目标各做一次，旧版均建出可编码的截图，新版均拒绝。进一步将目标区两个像素标为自有浮条，新版实际编码 PNG、再解码并逐点比较，剩下 14 个绿色和 34 个黑色，48 个像素全部匹配。[旧侧逐项](before-r2/junit.log) · [新侧逐项](after-final/junit.log)

Android 14 及以上改用系统按窗口 ID 抓取的 API。通过尺寸核验后把窗口图放回其物理显示坐标，保留合法手势的坐标原点。目标内容区以外及自有浮条位置遮黑。Android 11–13 使用系统整屏入口，若系统清单有另一应用、未知浮层或可能透出的下层重叠窗，即停止截屏。显示几何未知、外来遮挡与截图期间布局变化会给出相应原因及可采取的下一步。MCP 图片与路径图片均使用受限位图，编码前后重新核对窗口归属及几何，未成功返回的路径尽量清理。Android 34 合成两应用时，生产代码仅向平台请求了已确认的窗口 20。Android 33 合成次应用、未知浮层、低层系统窗三种场景时显示截图请求为零次，只有目标时才请求显示 0 一次。这两组入口测试使用平台失败回调计数，实际 PNG 检查由上一段独立覆盖。[截图与像素](../../../../app/src/main/java/com/deepseekharness/app/screen/ScreenScreenshotCapture.java) · [窗口筛选](../../../../app/src/main/java/com/deepseekharness/app/screen/ScreenTargetResolver.java) · [重验窗口](../../../../app/src/main/java/com/deepseekharness/app/screen/ScreenRequestContext.java) · [两种输出](../../../../app/src/main/java/com/deepseekharness/app/screen/MainScreenActions.java)

撤销时把已解码的 4×4 合成位图交给生产异步交付对象，在取回之前撤销，收到的结果为空且原位图已回收。目标仅占显示一部分时也逐点检查了偏移和边缘。整窗单独显示时目标原色保留，窗口缓冲区尺寸与系统登记的边界不一致时拒绝。这些测试针对现有授权和资源归还机制增加覆盖。[位图与撤销测试](../../../../app/src/test/java/com/deepseekharness/app/screen/ScreenScreenshotPrivacyTest.java) · [真实入口使用的合成窗](../../../../app/src/test/java/com/deepseekharness/app/screen/ScreenTargetResolverEvidenceTest.java)

## 窗口诊断中的标题

## 特权镜像的任务数与换应用时序

获取任务清单时最多查询 100 个。旧版收到刚好 100 条也认定已掌握全部应用，现在达到上限就返回归属未知。在含一条可见任务、其余不可见的 99 条合成清单中两版均识别目标。在达到 100 条时旧版继续认目标，新版拒绝归属。多应用可见、其它显示、租约切换、动作后新观察撤销等原有回归也一并执行。[旧侧计数](metadata-before/junit.log) · [新侧计数](metadata-after/junit.log) · [singleVisiblePackage](../../../../app/src/main/java/com/deepseekharness/app/vscreen/PhysicalScreenCore.java)

切换应用后，原线程先读图再清旧状态。即使读到空，也把队列当作已经排空。我们从新旧源码原样取出生产抓帧循环，用同一套五次合成读帧代替平台队列。第 0 次给原应用图，第 1 次应用已切换且读取抛错，第 2 次返回空，第 3 次是滞留图，第 4 次才是新图。旧版在读错前仍留有原缓存，复制第 0、3、4 号；新版在读之前清缓存，直到取到真实图并丢弃才接受后续图，只复制第 0、4 号。每张成功获取的图均关闭。两个完整对照轮次保留，带计时的轮次分别记录首次观察到旧缓存是否存在与整个循环完成的时间。[旧轮逐项](frame-queue-before-timed/run.log) · [新轮逐项](frame-queue-after-timed/run.log) · [旧轮计时](frame-queue-before-timed/metadata.json) · [新轮计时](frame-queue-after-timed/metadata.json) · [FrameQueueOwner 与 startCapture](../../../../app/src/main/java/com/deepseekharness/app/vscreen/PhysicalScreenDisplaySession.java)

## 证据范围

宿主验证了 OS 报告出的合成窗口、真实生产归属判断与发布对象、按窗口请求的 API 分支、合成 PNG 的逐像素结果和撤销后归还内存。系统厂商返回的窗口/任务清单是否完整、应用切换的极短区间、真实 Surface/HardwareBuffer 和读帧排队、桌面自由窗/通知/输入法等设备行为，仍需个人设备以外的受控设备做现场验证。特权整屏镜像的任务清单没有非任务浮层信息，因此“只报一个应用任务”不能证明每个镜像像素都属于该应用。Android 11–13 的普通无障碍入口也只能利用系统实际报告的窗口证据。没有向模型或网络发送截图。
