## 一个应用的授权能看到什么

原来特权 Core 镜像整个物理显示，再通过可见任务列表判断它属于哪个应用。通知等非任务浮层可以改变画面而不改变任务清单。在宿主上固定一条可见任务和同一包名，分别向旧管理器送入“仅目标”和“有额外浮层”的合成镜像回执。两次各返回 1 份图像标记及 1 个可操作观察 ID。新版本对相同的两份整屏输入分别调用采图 0 次，返回图像 0、观察 ID 0。独立的窗口授权可以读取对应窗口，默认自带工具走这条路径。

授权字段只有设备能力开关、任务身份及按包判断的屏幕确认策略。`ScreenConfirmationPolicy` 存模式、逐包规则和修订号；全局允许也只改变是否再询问应用。项目没有逐次确认的整屏 MediaProjection 通道。新 Core 在查询、配置时只读显示元数据，已经移除实体屏镜像生产者。旧 Core 在状态或配置回执额外夹带顶层图像、观察 ID、嵌套图像标记时，新管理器只拷贝规定的标量和配置数值。

检查范围包括单独读帧、附带回帧的点击、滑动、按键，以及内部多次采样的 benchmark。没有窗口来源和新窗口凭据时，特权输入不派发。原有权限开关和独立授权都满足时，Android 14+ 的默认 `/app/priv/frame` 和 `android_screenshot` 走 `/app/ui/screenshot`；已有新窗口凭据的点击、滑动走同一条受控输入链。状态、配置、关闭继续可用。自带 `android_key` 与独立虚拟屏保有各自原有入口。[旧侧整屏回执](mirror-before/junit.log) · [新侧整屏回执](mirror-after/junit.log) · [特权入口 appPriv](../../../../app/src/main/java/com/deepseekharness/app/HttpShellService.java) · [Core 路由](../../../../app/src/main/java/com/deepseekharness/app/vscreen/PhysicalScreenCore.java) · [元数据筛选](../../../../app/src/main/java/com/deepseekharness/app/vscreen/PhysicalScreenManager.java)

## 截图范围、撤销和可用路径

原无障碍截图在分屏时限制了坐标，但编码的仍是显示位图。相同 8×6 合成显示中有 16 个绿色目标像素、32 个红色目标外像素。旧生产截图对象保留全部 32 个红色，新对象将 32 个全部遮黑，16 个目标像素保持。另将目标内的两个位置标记为自有浮条，新代码编码 PNG 后实际解码检查 48 个位置，14 个是目标原色，34 个是黑色。目标几何未知或被挡住时，旧逻辑两种均接收图像，新逻辑两种均不交图。传入生产异步交付对象的 4×4 位图在取回之前撤销，结果为空且位图回收。文件与 MCP 分支共用受限位图；写文件或者编码后再次复核授权、当前目标及几何，未交付的文件尽量删除。[相同输入旧侧](before-r2/junit.log) · [最终逐项测试](window-scope-final2/junit.log) · [捕获与遮罩](../../../../app/src/main/java/com/deepseekharness/app/screen/ScreenScreenshotCapture.java) · [图片回传](../../../../app/src/main/java/com/deepseekharness/app/screen/MainScreenActions.java)

- **Android 14 / API 34。** 模拟真实窗口对象和按窗口的成功系统回调。生产代码完成解码、黑色背景上的物理坐标定位、PNG 编码和一次性凭据签发。额外应用仍存在时只向系统请求了窗口 20，整屏接口调用为零，目标首尾像素与外部像素均验证。缓冲区尺寸不等于登记窗口时拒绝。
- **Android 11、12、12L、13 / API 30–33。** 分别载入对应 Android framework。每版各用仅目标、另一个应用、额外无障碍浮层、额外系统窗口四组输入。整屏采图合计 0 次，16 组均通过独立授权的目标语义树读取，能看到合成目标控件文本，外来控件文本不出现。`android_get_state` 取得窗口自己的 `treeId` 和 `nodeId`，`android_node` 使用节点支持的操作。
- **独立虚拟屏。** 同一矩阵执行了虚拟屏撤销与窗口证据测试。系统Android 14+ 未连接无障碍服务时返回 accessibilityRequired=true，并给出 android.settings.ACCESSIBILITY_SETTINGS 设置动作，宿主未改变真实用户授权。

## 独立维护的真实调用链夹具
