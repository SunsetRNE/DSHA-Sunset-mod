# Build377 Shizuku 服务与 Binder 验收

build376 管理器解绑时，SDK 对服务发出的销毁事务在 DSHA 没有接收方法。在 Windows 上的 Robolectric 合成环境里，同时覆盖“服务是否关闭、原 UID 是否隔离、旧回调能否影响下一次连接”的 15 项检查，build376 通过 3 项，build377 通过 15 项。另用两代实际生成的 Proxy 和 Stub 互调，两个方向都通过。上述模拟均在 Windows JVM 完成。Android 实体设备、Shizuku 管理器、真实 root 及实际进程退出没有在此项中运行。

## 旧来源如何处理

历史审核 `docs/audits/build156/shellservice-source-provenance.json` 的争议文件就是 `app/src/main/java/com/deepseekharness/app/ShellService.java`。旧件带 CFR 0.152 标头，旧完整文件 SHA-256 为 `0fd0e42727d06130f7cd66fe7356ae57359e90287880440e7efbb64b4d8334a3`。按公开的 UserService/Binder 契约、工程内 `DeviceShellExecutor` 的策略接口、`BoundedProcessRunner` 的限制和 `RootShellMain` 的调用形态，重新编写了 Binder 壳、生命周期和通用子进程调度。旧协议字段、错误标记和翻译正文沿用，便于原调用方识别。为避免改变另一条已有授权通道，保留了可定位到本仓库独立提交的 root 专用参数策略和 ADB 会话逻辑（`5fdd92b6c717af7b4da69b0d350b3f18867d4ea1`、`c76408436ebdda93d15dcdf514782a61e584c728`），与新实例的子进程登记共用。这些方法没有出现在 AIDL 中。以前版本的外部原件作者或许可仍未查实，此次替换无法证明历史授权。

当前文件进入常规 Java 格式检查，`tools/java-format.lock.json` 移除了历史原件路径。格式保护测试改用临时、明确指定的受保护文件，8 个格式器测试通过。旧审核记录、旧源码和首轮失败日志都保留。对照 [SDK 指南](https://github.com/RikkaApps/Shizuku-API#userservice)、[管理器发出的单向事务](https://github.com/RikkaApps/Shizuku-API/blob/master/server-shared/src/main/java/rikka/shizuku/server/UserServiceRecord.java)、[服务登记键](https://github.com/RikkaApps/Shizuku-API/blob/master/server-shared/src/main/java/rikka/shizuku/server/UserServiceManager.java)、[官方用户服务启动实现](https://github.com/RikkaApps/Shizuku/blob/master/starter/src/main/java/moe/shizuku/starter/ServiceStarter.java)。本地锁定的 13.1.5 shared AAR SHA-256 为 `4659642c9339be0a26e9c65bb8648f7ad6d8f4a465f557993ccbc78802381635`，实际读取其中编译常量得到 16777115。

## 重放与逐轮结果

Windows 11 家庭中文版 x64，Temurin 17.0.20.1+1。Robolectric 4.15.1，Android SDK 34，JVM 开启断言，1 GiB 最大堆，2 个活动处理器，离线框架缓存。测试替换 Shizuku 管理器的授权、绑定及回调，不发送设备命令；进程使用假句柄，实际退出决策使用计数探针。虚拟时钟推进 15 秒，后台释放回执允许真实 JVM 等待最多 2 秒。每轮用同一份测试源码分别编译 376 与 377 的 AIDL、服务及客户端；其余不变依赖取本地 Gradle 编译缓存，详见生成的 `compile.args` 和 `junit.args`。

```powershell
Set-Location F:/DSHA_RESTART/artifacts/build377-local/shizuku
python replay.py before
python replay.py after
python mixed.py
python summarize.py
```

基线命令会返回 1，对应 12 个确实未达到的新期望。候选与互通命令返回 0。首次生成 AIDL 时，先遇到缺少 `--out`、缺少导入路径及 Windows 斜杠不一致；使用完整 Windows 原生路径、匹配的 `-I` 和输出目录后成功。这些是生成器调用错误，未计入测试数量。R1 候选 8 项中 2 败，检查发现测试管理器的静态移除数组跨用例累积；明确重置合成端点及登记状态后，R2 的 10 项全过。补管理器重启为 11/11，补专属进程与旧构造方式为 13/13，补不同实例假子进程为 14/14，补被拒清理恢复为 15/15。基线同批为 3/15。日志中可对照首轮和最终测试的方法名及原因。
