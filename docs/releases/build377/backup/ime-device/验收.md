# 系统输入法打开时的备份按钮

Android 11 专用 AVD 为 `DSHA_build377_lan_api30_x86`，物理 720×1280、320 dpi，使用真实 Google 输入法。初包的长说明截断见[前一轮记录](../compact-ui/%E9%AA%8C%E6%94%B6.md)。第一轮修复后的正式候选 `5d952daf` / APK SHA-256 `72917c42dee81df41e26f2d7977ba735b0e3c0c94a93803561272d6f6facbeaa`，收起键盘可操作，非全屏键盘出现后，无障碍树报告两钮，但其屏上位置被键盘盖住。WindowManager 记录浮窗已有 `adjust=resize`，系统也已经收短窗口，其 `LayoutParams` 仍要求固定 720×1088。按钮在 y=851–948，输入法从 y=686 开始。另在横屏实见 Gboard 打开全屏提取编辑器。[系统几何](../../lan/signed-dialog-r2/default-portrait-ime-windows.json) · [原签名包非全屏键盘截图](../../lan/signed-dialog-r2/default-portrait-normal-1795596762-first-password-keyboard-shown.png)

**实际改动。** `DshaDialogBuilder.sizeOnce` 保留原宽度算法，提供仅这个备份表单调用的 `wrapContentHeight()`。`NativeDataActivity.promptExport` 据此始终让高度按 WRAP_CONTENT 重测，普通对话框仍使用原高度上限。`PortablePasswordFields` 仅给新密码和确认两个输入框加标准 NO_FULLSCREEN、NO_EXTRACT_UI，要求支持的输入法保留横屏应用窗口。密码类型、关闭个性学习、Next 与 Done 继续生效。[四份源码完整路径和摘要](inputs.json)

**真实按键。** 独立测试包的包名为 `org.dsha.fixture.imebackup`，签名使用新建合成测试密钥。四个旧 DEX 及静态资源来自上面的签名 APK；两个新 Activity 用改名的实际生产源码，并设置相同主题及 ModernAndroidUi 回调；使用独立 UID 与应用目录。每轮输入两次相同的 24 个合成字符，明文框保持未选。下面“点入”均指键盘仍弹出时实际点击，系统切换到 DocumentsUI 的 PickActivity 并收到 ACTION_CREATE_DOCUMENT，随后按返回取消。测试没有保存备份或停止 DSH。

**普通库存测试。** 在真实 377 资源与 Windows/JDK 17 Robolectric SDK 34 worker 中，效果由 `NativeDataChoicesTest.tallBackupDialogRetainsWrapHeightAndStandardTabletWidthAfterSizing` 固定。给真实构建器和真实对话框一个超高的测量结果，调用同一个生产尺寸回调，在 800dp 大屏验证专用表单与普通对照窗宽度相同、均使用原有上限，前者高度继续 WRAP_CONTENT，后者仍采用原来 1152px 高限。窗口令牌在该宿主环境可能缺失，测试直接触发尺寸回调；系统实际派发与键盘覆盖见上表。旧类 6/7，失败为预期 -2、实际 1152；候选整类 7/7、17.089 秒，含对密码类型、IME 标志及既有 SAF 取消、旋转、进程丢失的断言。[旧侧原始输出](host-before-final/junit.log) · [新侧原始输出](host-after-final/junit.log) · [源码格式核对](format.json)
