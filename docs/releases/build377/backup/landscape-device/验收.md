正式 377 候选 `0efbf4d26a86d5cb99b4c22d56aa6e6971fd1d61`、APK SHA-256 `292f89da4d199c7364aba77b441370f7c75e276d65f11ecc82c29a6f60a45ba8` 在短横屏上可以点进系统选择器，但 Gboard 开着时，白色面板只有 88dp 高。静置三次截图一致，选择位置文字只剩 68.48% 墨迹、取消只剩 66.99%，各只有 16/21 行字形像素；正在编辑的密码框可见面积为零。独立测试包的旧源码、同一组资源和同一 Gboard 重现了相同的百分比。[签名 APK 静止像素](../../final3/lan/landscape-label-pixels.json) · [旧分支原生边界](before-wide-normal/result.json) · [旧分支截图像素](before-wide-normal/pixels.json)

**改动。** `NativeDataActivity.promptExport` 在宽度不足 600dp 或高度不足 480dp 时，将备份标题、说明与密码放进同一个滚动区，仍设置无障碍标题及窗口标题。该表单省去上下背景空白。操作仍使用原有两个 Material 按钮。页脚按真实按钮内容测量，按钮从两行排回一行时，将多占的高度还给输入区。宽大屏的窗口宽度仍按既有上限计算。其它确认弹窗与密码、明文选择、提交、取消的处理函数沿用原实现。[源码](../../../../../app/src/main/java/com/deepseekharness/app/ui/NativeDataActivity.java) · [生产文件格式前后同一组 Java token](format-production.json)

## Android 系统对照

## 失败、重试与适用范围

- 首版仅对短横屏合并标题、去上下间距，默认字号已通过。1.3 倍的横屏按钮字形完整，实际焦点栏却只露出 4/105px，墨迹为零。查到已换回单行的按钮区仍将先前两行高度当作自己的最小高度。停止用按钮内容填满自己保留的视口后，大字号单行按钮栏自然高 162px，输入栏完整可见。[失败](compact13-land-rescue/pixels.json) · [修后层级、按钮和焦点栏](compact-check-r3-rescue-1.3-1/result.json)
- 初次大字横屏脚本只写系统设置，实际两轮回到了竖屏，排除在横屏结果以外。后改用 API 30 的 `wm set-user-rotation lock`，每次取样都核对系统实际旋转。首次用了较新系统的命令名，被 API 30 拒绝，于是重启试验。[发生在竖屏的原件](after-large-landscape-rescue/result.json) · [命令名不匹配](large-land-r2-rescue/result.json)
- SDK 34 宿主方法 `NativeDataChoicesTest.compactFormsKeepAFullPasswordRowAndBothLabelledActionsAboveIme` 检查标题可滚动、紧凑表单边距、实际可用输入高度、两按钮和 1.0/1.3 字号。模拟从窄宽度到真实宽度的布局时，直接再次 measure 最初复用了旧结果，修正为重新触发 traversal。旧版 7/8，预期旧背景上边距为 0、实为 48px；候选完整 8/8。本方法与原有七项均在实际 Gradle worker 类路径和 377 资源上运行。[人工测量缓存日志](host-geometry/junit.log) · [旧版](host-before-final/junit.log) · [候选](host-after-final/junit.log) · [格式器记录](format-final-test.json)

**重放。** 在本目录执行 `python -X utf8 build_probe.py <新目录名>` 创建独立包。获得此专用 AVD 的操作权后，执行 `python -X utf8 matrix.py <新矩阵名> <试验包目录名>`。设备脚本固定 ADB 端口、序列号、AVD 名及 Android API。宿主重放用 `python -X utf8 replay_host.py <新目录名> candidate`。所有模式均使用新输出目录，保留编译参数、退出码、起止时间、原始 PNG 及各项观测。像素数值针对该系统、字号和英文主题。实际设备、第三方输入法和 OEM 字体须按对应环境验证。[逐像素复核](analyze.py) · [矩阵执行器](matrix.py)


**旋转与恢复现场。** 格式化后精确源码另建独立测试包，设备 base.apk 实算 SHA-256 `34d7921894d79af32c44759cdbe3888ae939c623c86efc887c6d8ce8c5c5fd16`。普通竖→横（54.844 秒）和救援横→竖（53.719 秒）都先填满两个 24 字符密码，旋转后原生字段长度均为 0，保持同一导出入口。再次输入后仍在 Gboard 开着时点入系统选择器并返回。最后恢复原始 720×1280、320dpi、font_scale 未设置、自动旋转开启及 user_rotation 0，测试包进程停止，前台回到 DSHA。[普通旋转](rotation-final-normal/result.json) · [救援旋转](rotation-final-rescue/result.json) · [安装与归还](returned.json)


整版冻结源码 `365719301ebf8c35f87edc24bdce4edb503c46d5` 的 Windows Gradle r6 也执行本类八个方法，8/8、0 跳过，类用时 11.674 秒。此处含上表同一宿主方法，两个计数不累加。[全套中的本类 XML](windows-r6-native-data.xml) · [全套输出](../../windows-r6/gradle.log)

## 最终签名 APK 与实际系统文件入口

正式候选源码 `365719301ebf8c35f87edc24bdce4edb503c46d5`，APK 255,591,272 字节，SHA-256 `f6b7f9ecf53e71a20bebf4ce23d3c8cf643311a7cee5435ad281d2dec70235f2`，与 AVD 装机 base.apk 核验一致。实际签包又执行普通、救援 × 竖屏、横屏 × 默认、1.3 倍字号共 8 组。八组都在真实 Gboard 开着时点入 DocumentsUI 的 CREATE_DOCUMENT 并取消返回。32 个键盘开启观测中，两按钮合计 64 个字形掩膜 SHA 全部等于相同表单的收键盘参考；每处焦点栏实际可见遮罩字符。1.3 倍竖屏单行显示 19 个遮罩点，其余格为 24 个，输入长度均为 24。本段为正式签名 APK 的软件与专用 Android 11 系统结果，独立测试包和宿主回归另列。[签名回执](../../local-release/apk-signing.json) · [装机回执](../../lan/apk-upgrade-1795600590.json) · [正式包八格逐图结果](../../final4/lan/label-and-field-matrix.json)
