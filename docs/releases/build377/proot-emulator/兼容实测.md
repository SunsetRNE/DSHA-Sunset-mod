**最终 APK 的五个 ELF 已提取、逐件验摘要，并在原仿真器重跑。** build377 签名生产源码为 `15e7fcc285121d67efdfad11ce688fc0a81dd392`，正式 APK 为 255587176 B，SHA-256 `2e6f0324ebe4b52b143dcb2bf04800b1ce73c106a53b567de1afdafca5dba3d9`。四件可重建 ELF 及原共享内存库均与候选逐字节相同。九项功能检查全部通过。测试结束后已关闭专用虚拟机和专用 ADB server，5672、5673 和 5077 端口均无监听。[包含通知与布局的签名成品总回执](signed-final.json) · [从签名 APK 提取的五件](../local-evidence.md#local-1da9ef908ee7) · [关闭记录](closed.json)

原来的 PRoot、两个 loader 和 talloc 能运行，但无法将它们的成品字节完整追溯到一组可重建输入。本次在一台新建的 Windows QEMU 仿真器内，把可重建的四件替换进去做同一组功能对照。Android 运行参数参照 `source/build377-local/app/src/main/java/com/deepseekharness/app/runtime/ContainerRuntime.kt::applyEnv`。两个 loader、临时目录和动态库目录均通过该函数同名环境变量指定。独立应急启动另有自己的端到端检查。[候选原件与构建证据](../source-rights) · [四件与共享内存库的逐件 SHA](candidate2/cases.json)

Google 官方离线系统镜像 `arm64-v8a-30_r16.zip` 的已记录 SHA-256 是 097c2808a738ba4c19038b75a085750dd61a7178c0234b14ac5f8270dd8cff54。系统指纹为 `google/sdk_gphone_arm64/emulator_arm64:11/RSR1.240422.006/12134477:userdebug/dev-keys`。AArch64 系统级 QEMU 关闭加速，以 4 核、2560 MiB 运行。内核为 aarch64，Android API 为 30，SELinux 为 Enforcing。发起测试的 Android shell 是 UID 2000。新虚拟设备 `emulator-5672`、专用 ADB server 5077 和单独的测试密钥被限制在本地。所有命令都指定 host、port、serial，再检查专用 AVD 名。未调用个人设备或其 ADB server。[本次启动命令](launch.py) · [实例记录](launch-r1.json)

每轮计时从系统身份检查完成起，包含编译两个合成 guest、推送、逐件读回 SHA，再至 `--version` 的首个可用输出，以及全部检查结束。启动新虚拟机到首次保存已就绪的 Android shell 身份用时至多 161.339 秒。这些用时用于重放量级，不作终端用户的启动性能结论。

每轮先运行 PRoot 自身，随后各用默认环境与 `PROOT_NO_SECCOMP=1` 启动 Android 自带的 `/system/bin/sh`、ARM32 静态程序、ARM64 静态程序。两个合成程序分别通过 NDK r26d 编译，必须在虚拟根中打开特有标记文件，读到约定文本，并检查虚拟 UID 为 0。最后分别仅更改 64 位、32 位专用 loader 的路径使它不存在，再执行匹配位宽的程序。两次均退出 1 并提示找不到可用 loader。恢复正确路径的成功记录和个别预期失败都保留。这验证了对应 loader 在此环境确实参与执行。[每轮命令、ELF 表、输出、退出状态与时间（正式 376）](baseline1/cases.json) · [候选](candidate2/cases.json) · [guest 测试源码](guest.c)

首次候选运行在验证 AVD 名时遇到 Windows 控制台多返回一个空行，尚未写入任何 guest 数据。修正解析后仍严格核对完整名称和 OK，两组用例全部执行。[首轮识别失败](candidate1.log) · [重试输出](candidate2.log)

等候签名包时已暂停这台仿真器的虚拟 CPU。专用 AVD 中六个数据、加密与缓存磁盘文件合计逻辑大小 8996389376 B，F 卷实际分配 483852288 B，测量时同卷可用 347708248064 B。保留它们可在同一 guest 对照最终成品。其中只有合成试验数据。[虚拟机暂停读回](pause-before-sign.log) · [逐文件计量](avd-paused-storage.json)

## 重放

在工作区根目录运行。每轮使用新的纯字母数字 `--attempt` 名以保留原始记录。若上一实例已关闭，可先运行 `launch.py` 并等候专用 Android shell 就绪。若实例已在线则直接运行用例。

```powershell
$prootEvidence='F:/DSHA_RESTART/artifacts/build377-local/proot-emulator'
python -B "$prootEvidence/launch.py"
python -B "$prootEvidence/run_cases.py" --apk F:/DSHA_RESTART/artifacts/build376-formal-20261125/signed/dsha-0.2.2-rc.5.apk --attempt repeat376
python -B "$prootEvidence/run_cases.py" --candidate F:/DSHA_RESTART/artifacts/build377-local/source-rights/candidate --attempt repeatCandidate
```

可以将 `--apk` 指向签名后的 build377，脚本直接提取真实 APK 中的五件，再运行完全相同的测试。范围是官方 API 30 用户调试系统、此 ARM64 内核、上述两种启动参数及两个合成程序。应用普通 UID、实机厂商 SELinux 策略、不同内核和完整 Android 桌面渲染均不在这组数据中。
