## 第六步的资产和进程分别核对

两份正式包的 `assets/ubuntu-tools.bin` 都是 15517764 B 的 XZ，SHA-256 `0027c09c3a63493571dbe32a291ab83229c6c4f816e7285f849cabf8a15245f0`。在本机 Linux 文件系统上，分别以两份 APK 为来源，调用 build377 的 `BundledRootfsAsset.decode`、`TarGzipExtractor.extractSelected` 及项目的 `JvmBackupFileSystem`，各解出包含根目录的 2986 个条目。包版本标记和 dpkg 状态摘要 `f4edc364d3d98514ae7567063645013b2e36f3eb3493ce0076fcc270e4b248b2` 均匹配。376 完成用时 13.552 秒，377 用时 13.353 秒。首轮宿主脚本末尾的换行不兼容，归一为 LF 后重跑。[原始解压与校验读数](overlay-replay-r2.log) · [重放脚本](overlay_test.sh) · [真实生产调用](../../../../app/src/main/java/com/deepseekharness/app/runtime/ColdToolsInstaller.java)

在同一 r16 ARM64 guest 运行签名包 `lib/arm64-v8a/libdsha-session.so --birth-handshake /system/bin/sh -c …`。普通 adbd shell UID 2000、有 SELinux，虚拟机未开启 native bridge。验证了内核出生记录中的父进程、组、会话与启动时钟，然后才写入 `DSHA_START`。原件在两个用例里都进入 shell、创建独立标记文件并输出 `MARK_DSHA_START`。仅增加日志的同源码观察版分别读到 `waitpid` 的正常退出 0 与 17，均无信号。签包原件及观察版的组长都按源码在子进程退出后自行结束进程组，宿主读到 137，随后组长和子进程的 /proc 条目均消失。试验器四次均未发出强杀。完整四项 58.625 秒。[原始四轮、两个 ELF 摘要、身份和回收记录](launcher-r3/results.json) · [重放脚本](test_birth.py) · [模拟器关闭](stopped-session-r6.log)

前两轮记录了工具能力差异。第一轮子 shell、握手和标记已经成功，附带的 `ps` 列名不受这个系统支持。第二轮该内核不提供所选 /proc children 节点，最终改读现场确认支持的 `ps -A -o PID,PPID,NAME`，并按父 PID 取子 PID，再核对其 /proc 条目。四个成功用例均使用同一种最终检查。[第一轮完整结果](launcher-r1/results.json) · [第二轮记录](birth-r2.log)

另一台 x86_64 转译机上，精确 Android 应用首次部署在工具状态已核验、发起 `EXEC runtime=proot isolated=true` 后失败。独立普通应用夹具进一步捕获了 `ProcessBuilder$NullOutputStream.write` 的 `IOException: Stream closed`。在该转译环境，同一观察版记录到子进程在进入 shell 之前收到 SIGSEGV。r16 原生 ARM64 对照说明相同程序和命令在该系统 shell 中能进入子 shell。普通应用的 UID 与进程域另行验收。[转译机产品阶段](../lan/cold-stage-events.json) · [普通应用栈](../cold-stream/process-r4/result.txt) · [转译对照](../cold-stream/observearm-r1/result.txt)

## 第二份官方 AOSP ARM64 镜像

新建独立 AVD，使用另一份已验证的官方 Android 11 AOSP `arm64-v8a-30_r02.zip`。官方目录标 r02，镜像自身的 `source.properties` 标 revision 1。ZIP、内部 15 份文件、每项 CRC 与展开后摘要的核查在镜像回执中。R5 首次运行将单独的镜像目录用作 SDK 根，模拟器报找不到 SDK；R5b 使用已有官方 SDK 工具并将 `-sysdir` 直接指向 AOSP 内容，随后成功启动 ARM64 内核。专属端口为 5080、5668、5669。[镜像验证](../local-evidence.md#local-c9c43dd7b7a4) · [R5b 命令](launch-r5b-aosp.json)

R5b 实际系统指纹 `Android/sdk_phone_arm64/emulator_arm64:11/RSR1.210722.013.A4/10160917:userdebug/test-keys` 与 r16 不同。普通 adbd shell 为 UID 2000，SELinux Enforcing，native bridge 为 0。zygote 在系统媒体库初始化阶段重复 SIGSEGV，package 和 activity 服务没有注册，已有系统包 `android` 也无法查询。对 255587176 B 的签名 build377 再走正常 Android 安装，3.250 秒后收到 `Can't find service: package`，未产生安装路径或普通应用 UID。因此无法进入这一固定镜像中的首次部署、第六步、备份导出或系统文件选择器。崩溃日志含 `app_process64` 与 `/apex/com.android.media.swcodec/lib64/libcodec2_vndk.so`。两次都在应用代码开始执行前失败。[R5b 系统安装步骤和崩溃栈](install-r5b-r02.json) · [引导到系统服务的各次现场读数](r5b-health.jsonl)
