# 冷部署第 6 步的 Stream closed

**build377 的离线工具归档能够在这台 Android 11 模拟器上完整解压。两轮实际部署都在开始检查 PROOT 之后失败。独立探针复现了同一错误，定位在应用给隔离启动器发送放行口令的 flush。** 在同一台 x86_64 模拟器上，ARM64 启动器执行 fork 后，父进程能收到新子 PID；加观察点的同源码版本实测，子进程被 SIGSEGV（11）终止，尚未输出 child 分支第一条记录、也未执行系统 shell 的第一条文件标记。父进程按现有设计回收进程组，Java 随后可能看到已关闭的标准输入管道。此结论适用于已经测试的 API 30 原生桥环境。[产品两轮阶段记录](../lan/cold-stage-events.json) · [正式二进制的完整 Java 堆栈](process-r4/result.txt) · [ARM64 子进程的 waitpid 原始状态](observearm-r1/result.txt)

**适用范围与可改之处。** 此处可单独改善产品报错，在发送或 flush 放行口令失败时提供握手阶段、能够核实的 supervisor 退出状态，仍核对身份、保全诊断并执行原有清组协议。归档读写、十六进制摘要和二次 close 均已有实际签名资产的通过记录。child SIGSEGV 的精确指令地址、原生桥内部故障点及 ARM64 真机上的表现，本专项没有相应证据。裸 x86 shell/隔离命令运行成功只涵盖这段监督协议；完整 ARM64 Ubuntu/proot 在该设备上的可用性需由对应部署记录说明。

## 轮次及重放

另做一次 **ACK 故障新提示的源码覆盖层复验**。普通测试 UID 10182 先核对实际安装的原签名 APK 为 2e6f0324…，原签名 ARM64 launcher SHA-256 为 `12ace2a08056105a663f0ebc492e568d8322a6b252550a16bc05668ed9a58ed5`。加载时只将新的 IsolatedInstallProcess 与生成的文案 dex 放在原产品类之前，覆盖层 5252504 字节、SHA-256 `c17ed7b033bb7e7db5c7e7dede69b3fc253de5e1ef8092fc6985aa9705442e17`。两个合成命令在同一发送放行阶段失败，中文和英文分别说明监督进程已退出、**经当时 exitValue 核实的 137**、系统 x86 与应用支持 ARM64，并指向设置里的诊断。底层 IOException: Stream closed 作为 cause 完整保留，系统 shell 前后文件标记仍未出现。该结果验证新提示和原有失败语义；整包签名后的结论由对应的成品验收绑定。[中英文原始堆栈及探针绑定值](ackoverlay-r1/result.txt) · [覆盖层](../local-evidence.md#local-28406a6c39d1)
