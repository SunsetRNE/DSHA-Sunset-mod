- Refuses to launch the host itself onto the virtual screen (T76): `/app/vscreen/launch` no longer accepts DSHA's own package as the target. The system does not create a separate instance for a secondary display; it reuses the same running process, and the WebView already bound to the default display crashes with a `libmonochrome` null pointer on the secondary display (relay device evidence: display 4, main-thread Looper entering WebView, reused running process 14715). The bridge refuses before any authorization prompt, the Manager before claiming, and the Core before sending `am start`, all through the same check, returning `VSCREEN_SELF_LAUNCH_REFUSED` (`state=NOT_SENT`, no launch command is sent and there is no crash); the built-in plugin classifies this code as pre-dispatch, the native app picker no longer lists the host, and the result page shows a Chinese/English reason. This is a safety refusal, not support for secondary-display self-launch; supporting it later requires `createDisplayContext` with a separate WebView instance. The runtime descriptor is regenerated (runtimeId `6bea62f2`); fixed inputs are not rebuilt.
