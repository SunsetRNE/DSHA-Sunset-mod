# DSHA 0.2.1-rc.5-20261113.1340-dsh0.2.2-rc.1 / build364

- Сборка безопасности данных и наблюдения за запуском (одно видимое пользователю исправление точности данных): после build363 в build364 вошли исправления RC1-миграции P1a/P1b и замечания ревью P0/P1/P2, управляемые Kotlin-входы K0 и архитектурные границы, базовый блок наблюдения за запуском S0 только для чтения, а также внешний путь adb/fastboot и исправление первого proroot-пробного запуска. **Пользователю видна консервативная fail-closed семантика RC1-миграции**; K0 / S0 — это инфраструктура сборки и диагностики, остальное — исправления путей устройств и документация.
- RC1-миграция (безопасность данных, видимо): протокол результата переходит на `resultVersion=3` и разделяет «копии содержимого, перепроверенные в этом запуске», «историческое завершение» и «результат записи неизвестен». Запись миграции разрешена только после полного перечитывания защищённых копий в этом запуске; историческое завершение разрешает лишь обычный запуск без записи миграции и требует committed-квитанции и полного реестра settings. Попадание в кэш привязывается к generation + sourceSha256 + ожидаемому набору разделов, а не синтезирует успех из старых булевых значений.
- RC1-миграция (продолжение): сверка history-only не создаёт и не обновляет разделы settings и не перезаписывает значения, изменённые пользователем позже; отсутствующий исходный раздел или состояние pending/writing/unknown возвращает pending/unknown без записи. Уже отправленные записи с неизвестным исходом не повторяются автоматически. Список сохраняемых данных проецирует историческое завершение / ожидание / неизвестность из реальной формы current; неизвестные записи остаются доступными только для чтения и не дают права на автоматическое восстановление или удаление.
- Наблюдение за запуском только для чтения (инженерия): S0 добавляет счётчики только для чтения для остатков остановки, сканирований, guest-хелперов, попаданий подготовки и цепочки Node→аутентификация; они попадают только в диагностику запуска и существующие журналы и не меняют порядок, ожидание и проверки разрешений.
- Управляемые Kotlin-входы (инженерия): K0 включает `.kt` из управляемых деревьев в `runtimeId` и архитектурные проверки, добавляя негативные контроли компиляции/формата Kotlin и дублирующихся ключей; поведение выполнения не меняется.
- Пути устройств и пробный запуск обслуживания: поиск библиотек внешних устройств дополнен `usr/lib/aarch64-linux-gnu/android`, чтобы находить adb / fastboot; первый proroot-пробный запуск управляемой среды больше не падает на ENOENT при перечислении профиля, поэтому страница обслуживания не выполняет лишний неудачный пробный запуск.
- Документация и приёмка (только документация): квитанция приёмки на устройстве build363, анализ первого сбоя пробного запуска, проект RC1-миграции и внешний ответ, а также оценка цепочки запуска внесены в индекс документации.
