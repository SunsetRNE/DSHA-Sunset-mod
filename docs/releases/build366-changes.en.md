# DSHA 0.2.1-rc.5-20261114.1717-dsh0.2.2-rc.1 / build366

- Plugin management, device capabilities and the file workbench: after released build365, build366 lands A6 plugin management P0–P4, A7 device/screen work S1–S5, A2 file-workbench slice3/4 and A5 S1 page environment sampling. A8 phase one only freezes its task baseline; A3 slice4 and later A5 behavior slices have not shipped.
- A6 plugin identity and state: installed bundles, profile selection, entryId/moduleHash/parent groups, literal disable intent and observed runtime state are separate facts. Lifecycle phase distinguishes pending/loading/unloading/active/failed/null. Missing content proof, stale evidence or a generation/identity mismatch remains unverified. Preflight, browser readiness and historical records do not prove Loader success; an unattributed startup failure does not disable every attempted plugin.
- A6 results and cards: lists, compact cards and details prioritize queued, cancelled, timed-out, failed and unconfirmed results. Confirmed submission and a stale catalog are shown separately. Compatibility checks engines.dsh first, otherwise every DSH peer; known incompatibility, unsupported platforms and check failures block submission. Exact-version exemptions are read-only. Saved changes without hot-application proof show restart-required and take effect after restart. New states and reasons have ten-language text.
- A6 unknown-result boundary: an unverified exit during a plugin mutation retains the environment lease. Restart the app and inspect the runtime maintenance page; candidates and unfinished transactions are not replayed, and restarting does not prove success. Trusted A5 exit proof and deployed-content proof are not fully connected, so confirmation or status text cannot clear conservative unknown. An unknown read-only query makes the catalog stale and releases its shared lease instead of retaining the environment permanently. A real directory without package.json is no longer shown as an available plugin. User disable intent, safe mode and system/user separation are preserved.
- A7 device authorization and channel facts: authorization snapshots, generations and pre-execution checks share a device authorization fence. User switches, authorization requests, connection state and actual channel capabilities remain separate. Shizuku callbacks and Root paths recheck current identity and explicit policy; revocation, generation changes or unavailability cannot reuse an earlier success. No system permission or arbitrary-command entry is added.
- A7 physical and virtual screens: physical semantic nodes, screenshot coordinates, input and navigation keys use their respective action evidence. Virtual coordinates, nodes, editors, anchors and keys bind their five evidence classes separately to the Core, generation and target. Evidence is not silently exchanged, screens do not serve as fallbacks, and UNKNOWN is never replayed. A new observation is still required after an action. Password-text blocking and sensitive-screen confirmation/handoff policies remain in force.
- A7 read-only Root module inventory: a new device-page entry reads only on explicit request and shows bounded information from the fixed /data/adb/modules directory. Fixed-FD probing checks UID0, the current installation and file identity against reviewed Magisk/KernelSU/APatch samples before executing the opened object. Unknown versions or ambiguity are rejected without searching PATH or switching to Shizuku/ADB. The inventory does not read scripts, recurse or offer install/enable/update/remove actions. Failed or partial reads are not presented as a complete empty list; pausing or authorization changes discard old results. Fourteen new messages cover ten languages. Source samples do not certify manager or device compatibility.
- A2 file workbench: the Cross-app file access settings page adds a file-workbench (import/export) switch, off by default; the workspace files page shares authorization, browsing and history entries. Transfers recheck authorization/epoch, read/write bits and local file identity before transfer and publication. Mid-transfer revocation, cancellation and timeouts retain typed results without automatic replay. Bounded history stores no URI, full path or content. The Provider remains a trust boundary; a failed external in-place overwrite can leave an incomplete file, and content-level credential-copy prevention is not promised.
- A5 and engineering: S1 only consolidates read-only environment sampling for pages while preserving previous predicates. It does not claim to fix latest/trial wiring or stop automatic APK checks. After A7 integration, host compilation lists include the action-evidence class and Root inventory tests use Robolectric for real JSON. Those fixes do not establish full build366 CI or device acceptance.
