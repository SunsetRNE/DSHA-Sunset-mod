# DSHA 0.2.1-rc.5-20261115.1335-dsh0.2.2-rc.1 / build367

- APK updates (M17): checks now require a user action. Startup, returning to the app, window focus and the first opening of the update page no longer check automatically or prompt for an upgrade. An application owner manages downloads and the serial queue; recreated pages observe the original task. Permission and installation results only continue the user's original request; stale callbacks do not create a new request, and UNKNOWN is never replayed.
- Built-in plugin enablement (T2): fixes installed built-ins with exact managed proofs being blocked by third-party import rules when enabled. Automatic default-disable markers are recorded separately from user intent. User disables and historical empty markers with unknown origin remain intact across upgrades. The bundled dsh-web-mobile 3.3.5 version and its default-enabled policy remain unchanged.
- Startup recovery (S1a/S1b): adds Kotlin shadow sampling of stop facts and a pure handoff contract. S1a records facts without replacing the existing stop decisions. S1b consumes a handoff proof once, only during protected recovery with no plugin selected for disabling, and rechecks the current identity and scene before use. An ineligible request keeps the original path before entering handoff; after entry, UNKNOWN, object changes or invalid authority block execution instead of becoming a cache miss and replay. Ordinary startup and manual stop keep their original paths. This is not an exit proof for every path and does not terminate by bare PID or port.
- Backup stream bridge (A3): connects the Rust envelope stream bridge and fixes the bounded-stream, failure and cleanup contracts. JVM remains the default backend; Rust requires the existing enablement and availability conditions. A selected Rust stream never switches to JVM to reread or rewrite after failure. The v5 archive format, integrity checks and restore semantics remain unchanged. APK off mode bundles no Rust library; Android Rust streaming and power-loss recovery have not been accepted on a device.
- Kotlin migrations: 18 contract files, four M17 files, and the SAF (15), download/transfer (8) and network-health (3) Java files move to Kotlin. Real Java consumers and existing behavior are checked per domain. ABI reports explicitly record visibility, final and compiler-added member boundaries; seven former contract Java records no longer retain record metadata, so bit-for-bit ABI equality is not claimed. SAF "Cross-app file access", download queue, recovery/publication and network-health rules retain their existing semantics, with no new manifest permissions or data format.
- A8-P1 engineering foundation: fixed toolchains and build conventions, shared source layout, compilation-origin proofs, repository-wide fresh-test aggregation, the frozen test-identity baseline and unit contract proof become gates. Generator sources and the 93-item runtime recipe are synchronized. Third-party notice scanning covers build-logic; fixes address YAML boolean conversion of the release workflow's off option and the missing main-Java compilation proof. The source-hygiene UUID scan now covers `.kt`.
- Rust APK candidate: adds source and byte-reproduction checks for same-commit arm64 artifacts in an explicit prebuilt dry-run path. The release candidate uses off and bundles no Rust library. The pre-existing prebuilt Provider path defect remains unresolved; native artifact builds and host differential results are not evidence of successful Android loading.
- Evidence and retained scope: T1 only records read-only evidence about plugin disabling and segmented loading in portrait; the single-tool privileged-plugin contract remains a design draft. These records do not establish new pagination, a performance fix or a new privileged entry point. Device authorization, password-text blocking and sensitive-screen policies retain their existing boundaries.
