# DSHA 0.2.1-rc.5-20261114.1030-dsh0.2.2-rc.1 / build365

- Restore-plan, migration-safety and terminal-lifecycle fixes: after build364, build365 lands A3 slice2/3, RC1 hardening, A4 terminal/process identity work, and K1 tooling/gates plus the R3 Rust gzip side path. A5/A7 task baselines and review records are documentation; their later implementation slices are outside this build.
- A3 slice2/3: restore previews project the existing plan into read-only PlanView v1. Submission rebuilds the view with the current time after checking the source digest and validates it before building candidates or committing the host transaction. JVM validation is active; the Rust second implementation runs only when its backend is enabled and available. Invalid plans, disagreement or an unverified Rust result stop submission and preserve the original and private slot. Explicitly unsupported projection cases retain the existing JVM restore path. PlanView is not stored in the archive; the v5 data format and restore semantics are unchanged.
- RC1 migration hardening: secret-field projection follows the real SettingsForms schema reference graph, including nested and composite shapes; unknown schemas are rejected before dispatch. Existing ledger diagnostics are scrubbed without copying secret values into new records, while full settings readback still verifies the actual update. An exception after `settings.update` is dispatched remains `unknown`; error text cannot authorize an automatic retry.
- RC1 historical evidence: a legacy ledger missing `expectedSections` cannot prove completion from its own surviving keys; a fallback checkpoint must carry matching ledger provenance. Missing, malformed or contradictory evidence remains `unknown`. Some generations completed before build364 and later reused by build364 can therefore block ordinary and safe startup when neither trusted evidence source exists. Originals and read-only retained records remain available; this build keeps that conservative block and adds no bypass or automatic re-import.
- Java↔CJS startup handoff: cached historical preparation atomically writes and reads back the current startup identity and `history-only` mode before authorization. CJS checks the same generation and input binding; a missing or changed ledger cannot turn this handoff into a new settings update. Historical business receipts and later user edits are preserved. The backup/data format is unchanged.
- A4 terminal/process identity: guest exit requires two empty-session observations, including the natural-exit path; unreadable identity, interruption or remaining members retain the unconfirmed state. Session IDs are reserved before starting a backend and never reused. A single tab is removed only after that session's exit is verified. An unknown UID is reported as unreadable identity rather than a different app. Finite scans are not an atomic proof against arbitrary daemons.
- A4 acceptance tooling: debug instrumentation replaces exactly 30 old `targetPackage` values with the current application identity; the obsolete terminal lifecycle fixture is retired. The current audit observes rebuilt activities and verifies only the tabs it creates. Host PTY-handshake tests use the production C source, but do not establish Android JNI, rotation, language-switch or proot/proroot device acceptance.
- K1/R3 engineering: tooling and gates tighten scanner classification, constructor/shape assertions, native-test delegation and self-contained contracts. R3 adds bounded single-member gzip `archive_pack/unpack`, the JVM bridge and differential coverage; the Rust backend is off by default, its `.so` is not bundled, and the backup envelope call sites remain for A3 slice4. These changes add no user-facing option and do not change the archive format.
