# DSHA 0.2.1-rc.5-20261114.1030-dsh0.2.2-rc.1 / build365

- 복원 계획, 마이그레이션 안전성, 터미널 수명 주기를 수정하는 빌드: build365는 build364 이후 A3 slice2/3, RC1 보강, A4 터미널 및 프로세스 식별, K1 도구/게이트와 R3 Rust gzip 별도 경로를 통합합니다. A5/A7 작업 기준선과 검토 기록은 문서이며, 후속 구현 슬라이스는 이 빌드에 포함되지 않습니다.
- A3 slice2/3: 복원 미리보기는 기존 계획을 읽기 전용 PlanView v1로 투영합니다. 제출 시 원본 다이제스트를 다시 확인한 뒤 현재 시각으로 뷰를 다시 만들고 검증을 통과해야 후보 구성과 호스트 트랜잭션 커밋을 진행할 수 있습니다. JVM 검증은 활성화되어 있으며, Rust의 두 번째 구현은 백엔드가 활성화되고 사용 가능한 경우에만 참여합니다. 잘못된 계획, 두 구현 간 불일치, 검증되지 않은 Rust 결과는 제출을 중단하고 원본과 비공개 슬롯을 보존합니다. 투영 미지원으로 명시된 경우에는 기존 JVM 복원 경로를 유지합니다. PlanView는 아카이브에 저장하지 않으며, v5 데이터 형식과 복원 의미론은 바뀌지 않습니다.
- RC1 마이그레이션 보강: 실제 SettingsForms schema 참조 그래프에 따라 비밀 필드를 투영하며 중첩 및 복합 형상도 처리합니다. 알 수 없는 schema는 전달 전에 거부합니다. 기존 원장의 진단 정보는 다시 비식별 처리하고 비밀 값을 새 기록에 복사하지 않으며, 전체 설정 재읽기는 실제 update를 계속 검증합니다. `settings.update`가 전달된 뒤 예외가 발생하면 `unknown`을 유지하며, 오류 문구를 근거로 자동 재시도하지 않습니다.
- RC1 과거 증거: `expectedSections`가 없는 기존 원장은 남아 있는 키만으로 완료를 증명할 수 없습니다. 대체 checkpoint에는 일치하는 ledger provenance가 있어야 합니다. 증거가 없거나 형식이 잘못되거나 서로 모순되면 `unknown`을 유지합니다. 따라서 build364 이전에 완료된 뒤 build364에서 재사용한 일부 마이그레이션 세대는 두 증거원 모두에 신뢰할 증거가 없으면 일반 시작과 안전 시작이 모두 차단될 수 있습니다. 원본과 보존 기록은 계속 읽기 전용으로 볼 수 있습니다. 이 빌드는 이 보수적 차단을 유지하며, 우회 진입점이나 자동 재가져오기를 추가하지 않습니다.
- Java↔CJS 시작 인계: 캐시된 과거 prepare는 허용 전에 이번 startup 식별 정보와 `history-only` 모드를 원자적으로 기록하고 다시 읽습니다. CJS는 동일한 세대 및 입력 바인딩을 확인하며, 원장이 사라지거나 변경되어도 인계가 새로운 settings update로 바뀌지 않도록 합니다. 과거 작업 영수증과 사용자가 이후 수정한 값은 보존합니다. 백업/데이터 형식은 바뀌지 않습니다.
- A4 터미널 및 프로세스 식별: guest 종료에는 빈 세션을 두 번 관측해야 하며, 자연 종료 경로에서도 이중 스캔을 수행합니다. 식별 정보를 읽을 수 없거나 중단되거나 구성원이 남으면 미확인 상태를 유지합니다. 세션 ID는 백엔드 시작 전에 예약하고 영구적으로 재사용하지 않습니다. 단일 탭은 해당 세션의 종료를 검증한 뒤에만 제거합니다. UID를 알 수 없으면 다른 앱으로 잘못 표시하지 않고 식별 정보를 읽을 수 없다고 알립니다. 유한한 스캔은 임의의 daemon에 대한 원자적 종료 증명이 아닙니다.
- A4 인수 도구: debug instrumentation 선언은 기존 `targetPackage` 값 30개만 현재 앱 식별 정보로 정확히 치환하며, 기존 터미널 수명 주기 픽스처는 폐기합니다. 현재 감사는 재생성된 Activity를 관측하고 직접 만든 탭만 검증합니다. 호스트 PTY 핸드셰이크 테스트는 프로덕션 C 소스를 사용하지만, Android JNI, 회전, 언어 전환, proot/proroot 실기기 인수가 완료되었음을 뜻하지는 않습니다.
- K1/R3 엔지니어링: 도구와 게이트는 스캔 분류, 생성자/형상 단언, 네이티브 테스트 위임, 자체 완결 계약을 강화합니다. R3는 제한된 단일 멤버 gzip `archive_pack/unpack`, JVM 브리지, 차등 테스트를 추가합니다. Rust 백엔드는 기본적으로 비활성화되어 있고 `.so`는 패키지에 포함되지 않으며, 백업 envelope 호출부 연결은 A3 slice4에 남아 있습니다. 사용자에게 보이지 않는 변경으로 새 사용자 옵션을 추가하지 않고 아카이브 형식도 바꾸지 않습니다.
- 덮어쓰기 영향: 관리 시작 소스가 바뀌어 `runtimeId`는 **`8598a8dbf15d48773a41ff41e89935a9effcb5faaa0edc2b82f17dda223b5193`** 입니다(시작 입력 491개, 자산 입력 205개). **364→365 덮어쓰기 후 첫 실행은 전체 화면 관리 런타임 유지보수 페이지에 한 번 진입**하여 런타임 시험 실행을 수행하며, 개인 데이터는 보존합니다. 버전 번호 상승 자체는 runtimeId를 바꾸지 않습니다. 내장 `dsh-web-mobile` 3.3.5와 기본 활성화 상태는 그대로입니다.
- 고정 빌드 입력: `fixed-inputs-20261113`과 자산 `dsha-a-su-fixed-inputs-20261113-build364.zip`을 재사용합니다(716,787,167 B, SHA-256 `2c8dc3fa494a5faf6f65cafa966b47d234a3331c30396198005cedfccca82cad`). 의존성, 기본 Ubuntu, 복구 아카이브, 입력 잠금의 업그레이드는 포함하지 않습니다. 관리 소스 검증은 이 빌드를 위 descriptor에 바인딩하며, 런타임 recipe provenance는 아카이브 바이트와 별도로 확인합니다.
- 버전 및 범위: versionCode를 365로 올리며, 릴리스된 build364(tag `dsha-a-su-build364-20261113-134000` @ `1545e104`)를 기준으로 합니다. DSHA 개정은 `0.2.1-rc.5`, 내장 DSH는 `0.2.2-rc.1`을 유지하며, 패키지 `io.github.sunsetrne.dsha`, Mod 소유 인증서, 서명 방식은 그대로입니다. 기기 shell 가드, 권한 부여, 비밀번호 텍스트 강제 차단, 민감 화면 정책은 기존 경계를 유지합니다. 권장 tag `dsha-a-su-build365-20261114-103000`은 release 워크플로가 생성합니다.
- 검증 범위 및 한계: 릴리스 준비는 버전 식별, 생성된 10개 언어 설명, descriptor/소스 일관성, Java/Kotlin 포맷, 소스 위생, UI i18n, 문서 링크, 릴리스/CI 스크립트, 호스트 테스트 매니페스트를 확인합니다. 정확한 결과와 미실행 항목은 준비 기록을 따릅니다. 전체 단위 테스트, lint, APK/테스트 패키지 빌드, 서명은 계속 release 워크플로 게이트입니다. **build365 실기기 덮어쓰기 인수는 아직 수행하지 않았습니다**. 이전 build364 OnePlus 12 기록은 과거 증거일 뿐입니다. 364→365 유지보수 페이지 1회/READY 경로, 데이터 보존, RC1 차단, 터미널 닫기/회전/언어 전환은 기기 검증이 필요하며 더 넓은 ROM/기종 매트릭스를 주장하지 않습니다.
