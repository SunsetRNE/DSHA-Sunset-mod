# DSHA 0.2.1-rc.5-20261111.0600-dsh0.2.2-rc.1 / build357

- Stop/restart semantics completion (T150, `5dde9205f`): the host's SIGTERM exit wait budget rises from 3s to 6.5s, covering the bundled dsh's own 5s forced-exit cap and leaving headroom, so a normal close is no longer judged "unconfirmed"; `PENDING_EXIT` is no longer a terminal early exit and only a still-verifiable live process at the end of the budget reports unconfirmed; records retire only when the process disappears or the number is reused, and an identity or command-line change while waiting is recorded separately with no further signal sent, without blocking the main thread.
- Pre-start stop waits within the same window: the launch flow first gives the known launcher the same graceful exit window, then rechecks read-only within one 8s window, so an old instance that is still exiting no longer fails 10ms in with "launch failed: the app still has a Web that has not exited". If it still fails, the screen shows the three-part explanation (what happened / impact / next step) with the verified residual PID, a redacted command summary and the "Launch" retry entry instead of a bare internal string.
- Recovery adds STOPPED_PENDING (`core/WebSessionRecovery`, `core/WebSessionRestoreText`): "the user has stopped (stop sentinel)" is split out of compatible "version incompatible", with the new STOP_IN_PROGRESS / USER_STOPPED_EXIT_UNCONFIRMED reason codes; after a stop a restart no longer shows "the old instance version is incompatible / identity cannot be confirmed", does not fall into INCOMPATIBLE / UNKNOWN, does not authenticate and does not reconnect to the old instance.
- Force-stop fallback: when evidence is insufficient the UI no longer stops at "stop not completed" but shows the verified PID / command summary, why force stop is not possible and a 15s retry entry; the red line is unchanged — only a PID whose kernel birth identity was verified is signalled, never by name / port / bare PID, and the security boundary and protocol stay untouched.
- Debounce and phase reporting (P1 E/F): a duplicate stop in progress merges into the same request (one phase line, one conclusion callback), at most one force-stop candidate is prepared per 15s, and a manual stop shows the phase plus elapsed seconds in the status bar, turning the "stopping…" black hole into an explainable wait (`util/WebStopBudget`, `core/StartupStopWait`, `core/StartupStopText`, `core/WebForceStopText`, `ui/LaunchFragment`).
- T150 follow-up gate fixes (`bedaa5deb`): HarnessController returns to the 300-line facade limit (the redundant getProot() alias is removed and the seven HttpShellService call sites use proot()); the LaunchFragment force-stop failure dialog's "Re-verify" button reuses the existing "Retry" copy instead of adding a new ten-language string key; the managed descriptor is recomputed accordingly, so build357's `runtimeId` is **`c780bc22`** (205 inputs, replacing the T150-only `25235b80`).
