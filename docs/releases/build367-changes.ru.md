# DSHA 0.2.1-rc.5-20261115.1335-dsh0.2.2-rc.1 / build367

- Обновления APK (M17): проверка теперь запускается действием пользователя. Запуск приложения, возврат в него, получение окном фокуса и первое открытие страницы обновления больше не вызывают автоматическую проверку или предложение обновиться. Загрузками и последовательной очередью управляет владелец уровня приложения; пересозданные страницы наблюдают за исходной задачей. Результаты запросов разрешений и установки продолжают только исходный запрос пользователя; устаревшие обратные вызовы не создают новых запросов, действия со статусом UNKNOWN не повторяются.
- Включение встроенных плагинов (T2): исправлена блокировка включения уже установленных встроенных плагинов с точными подтверждениями управляемого содержимого из-за ошибочного применения правил импорта сторонних пакетов. Метки автоматического отключения по умолчанию учитываются отдельно от намерений пользователя. Пользовательские отключения и старые пустые метки неизвестного происхождения сохраняются при обновлении. Встроенная версия dsh-web-mobile 3.3.5 и политика включения по умолчанию не меняются.
- Восстановление запуска (S1a/S1b): добавлены теневой сбор фактов остановки на Kotlin и чистый контракт передачи. S1a записывает факты, не заменяя существующие решения об остановке. S1b однократно использует подтверждение передачи только при защищённом восстановлении, когда не выбран плагин для отключения, и перед использованием повторно проверяет текущую идентичность и состояние. До входа в передачу неподходящий запрос идёт по прежнему пути; после входа UNKNOWN, смена объектов или утрата разрешения блокируют выполнение, а не считаются промахом кэша с повторным исполнением. Обычный запуск и ручная остановка сохраняют прежние пути. Это не подтверждение выхода для всех путей; процессы не завершаются только по PID без проверки идентичности или по порту.
- Потоковый мост резервного копирования (A3): подключён мост потоков envelope Rust, зафиксированы контракты ограниченных потоков, ошибок и очистки. JVM остаётся реализацией по умолчанию; Rust требует соблюдения существующих условий включения и доступности. После ошибки поток, для которого выбран Rust, не переключается на JVM для повторного чтения или записи. Формат архивов v5, проверки целостности и семантика восстановления не меняются. Режим off не включает библиотеку Rust в APK; реальные потоки Rust на Android и восстановление после потери питания не прошли приёмку на устройстве.
- Переход на Kotlin: перенесены 18 файлов области contract, четыре файла M17 и Java-файлы SAF (15), загрузки/передачи (8), состояния сети (3). Реальные Java-потребители и существующее поведение проверены отдельно по областям. В отчётах ABI явно указаны границы видимости, final и членов, добавленных компилятором; семь прежних Java record в contract больше не сохраняют метаданные record, поэтому побитное равенство ABI не заявляется. SAF «Межприложенческий доступ к файлам», очередь загрузки, восстановление/публикация и правила состояния сети сохраняют семантику, без новых разрешений Manifest или формата данных.
- Инженерная основа A8-P1: в обязательные проверки включены закреплённые инструменты и соглашения сборки, общая схема исходников, подтверждения происхождения компиляции, агрегация свежих результатов тестов всего репозитория, замороженная база идентичностей тестов и unit contract proof. Синхронизированы исходники генераторов и рецепт среды выполнения из 93 элементов. Сканирование уведомлений о сторонних компонентах охватывает build-logic; исправлены преобразование опции off в логическое значение YAML в процессе выпуска и отсутствие подтверждения основной компиляции Java. Проверка UUID в рамках гигиены исходников теперь охватывает `.kt`.
- Кандидат APK с Rust: для явно выбранного пути prebuilt dry-run добавлены проверки происхождения и воспроизводимости байтов артефактов arm64 из того же коммита. Кандидат выпуска использует off и не включает библиотеку Rust. Прежний дефект пути prebuilt Provider остаётся неисправленным; сборка нативных артефактов и дифференциальные результаты на хосте не доказывают успешную загрузку на Android.
- Доказательства и сохранённые границы: T1 содержит только наблюдения без изменений о выключенном плагине и сегментированной загрузке в портретном режиме; контракт привилегированного плагина с одним инструментом остаётся проектным черновиком. Эти записи не означают новой пагинации, исправления производительности или новой привилегированной точки входа. Авторизация устройства, жёсткий запрет доступа к тексту паролей и политики чувствительных экранов сохраняют прежние границы.
