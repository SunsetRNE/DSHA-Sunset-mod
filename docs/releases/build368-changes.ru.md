# DSHA 0.2.1-rc.5-20261116.0500-dsh0.2.2-rc.1 / build368

- Сборка релиза Rust (по умолчанию prebuilt): release-production теперь по умолчанию использует rust_native_mode=prebuilt и включает в официальный пакет собранные и проверенные в том же run arm64 libdsha_rs.so и rust-native-receipt.json; off остаётся вариантом без библиотеки. Привязка артефакта того же run, сверка commit/run и повторная проверка каждого члена после подписи сохранены и прерывают выпуск при расхождении; официальная подпись по-прежнему выполняется release-процессом сертификатом Mod.
- Бэкенд Rust включён по умолчанию: DshaApp.onCreate() явно включает RustBackends после инициализации языка и настроек; при наличии библиотеки digest, archive и verify_plan по умолчанию идут через нативный путь. Поле процесса по-прежнему по умолчанию false, поэтому обычные JVM-тесты не зависят от загрузки нативной библиотеки; setEnabled(false) одним шагом возвращает JVM. Отсутствие .so, ошибка загрузки или несовместимая ABI оставляют JVM с типизированными причинами; после выбора Rust в verify_plan внутренние ошибки и расхождения реализаций остаются fail-closed и не перекрываются результатом JVM.
- Адаптация Android-пробы Rust: RustNativeInstrumentation сначала проверяет значение по умолчанию после запуска (включено, если в APK есть квитанция), затем временно отключает переключатель для исходных нативных дифференциальных проб и проб очистки после сбоя, а в finally восстанавливает исходное состояние и проверяет восстановление. Добавлены BACKENDS_NOT_DEFAULT_ON и BACKENDS_RESTORE_FAILED; сборка без .so и квитанции только фиксирует значение по умолчанию и не даёт ложного срабатывания.
- Исправления конвейера: исправлена раскладка загрузки доказательств тестовых пакетов одного варианта для dry-run/publish (bf491c77), чтобы test_packages=debug не срывался на объединении каталогов доказательств; восстановлены вызовы androidTest refreshPowerMode(Context) (872d48ac), разблокировавшие компиляцию androidTest в debug-сборках prebuilt.
