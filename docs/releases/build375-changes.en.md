# DSHA 0.2.2-rc.5-20261122.1650-dsh0.2.2-rc.5 / build375

- The app and bundled DSH are both at 0.2.2-rc.5. Android 11 and later arm64 devices can update `dsh.android.client` with the existing E7E3 signing certificate.
- Editing or selectively restoring workspace settings saves only the items that changed. Other settings keep their existing values or continue to inherit defaults. Changing just the subagent model pool’s toggle or model list saves only that item, so the other setting still follows changes to its default if it already inherited it. If you set only the retry count in a custom provider’s retry settings, its retry mode still follows the default when you change just its display name.
- After you return from the background or update the app, DSHA rechecks the previous workspace so an instance that has already exited cannot block startup. If you open Home while old copies are being cleaned up after an app update, DSHA waits and proceeds with the runtime update as soon as it can, avoiding a false “Readiness check failed” message.
- The startup log marks when startup timing ends. Logs after the web workspace is ready show runtime timestamps and are counted separately from startup.
- If you set the app to open the web workspace, tapping its icon while the native Home screen is in the background now opens the workspace. If the environment needs maintenance or the previous workspace needs verification, the app stays on the native screen.
- Saving a copy of a file from an app clone now reports success after the file has finished writing. When you turn ADB off from the wireless debugging pairing screen, the device execution channel shows the switch as off when you return. When a background ADB connection check finishes, times out, or is interrupted, the app cleans up that check’s own processes and keeps your existing wireless pairing.
- Virtual screen presets now show both the description and the available choices. Cancel keeps your current choice. If the DSHA accessibility service is not connected when you open the virtual screen nodes, the app explains that the service is unavailable.
- Removing a model provider deletes its configuration from the current profile and keeps the shared API key. To remove both, clear the key on that provider’s edit page and save first, then remove the provider. If a configuration edit is rejected, the key is retained.
- Changing a language that syncs with the app updates the current web workspace in place. If the workspace is already open, you return to the same web page after switching between light and dark themes. The desktop layout setting takes effect when a new web view is created. An open fault report updates its text and buttons too. The action to view the cause and repair options opens the recovery screen. Returning from it takes you back to the native Home screen.
- Settings-only backups collect portable native settings, model configuration, profiles, and presets. Plugin installation packages and duplicate archives are left out of this backup. Supported legacy settings and user-written profile declarations are preserved. A separate option controls the native API Key field. Full app backups and previously retained archives still use their own restore paths.
- Storage statistics mark categories that could only be read in part and show the bytes already counted. An unread size is shown as unknown, and a verified empty category shows 0 B.
- Skill details start with a preview. You can open the full source and read it page by page. The detail stays visible while a skill is moved to Recently deleted or restored, and the controls become available when the operation finishes.
