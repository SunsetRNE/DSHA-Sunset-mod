# DSHA 0.2.1-rc.5-20261116.0500-dsh0.2.2-rc.1 / build368

- Rust release assembly (prebuilt by default): release-production now defaults rust_native_mode to prebuilt, shipping the same-run arm64 libdsha_rs.so and rust-native-receipt.json inside the production package; off remains available to keep the library out of the APK. Same-run artifact binding, commit/run receipt checks and the post-signing member-by-member recheck are unchanged and abort on mismatch; the Mod certificate still signs through the release workflow.
- Rust runtime backend enabled by default: DshaApp.onCreate() explicitly enables RustBackends after language and settings initialization, so digest, archive and verify_plan use the native paths when the library is bundled. The process field still defaults to false, so ordinary JVM unit tests are unaffected by native loading; setEnabled(false) switches back to the JVM. A missing .so, load failure or ABI mismatch falls back to the JVM with typed reasons; once verify_plan selects Rust, internal errors or implementation divergence stay fail-closed and are never overwritten by JVM results.
- Android Rust probe adaptation: RustNativeInstrumentation first verifies the post-startup default (enabled when the APK carries a receipt), then temporarily disables the switch for the original native differential and failure-cleanup probes, restoring the initial state in finally and asserting the restore. It adds BACKENDS_NOT_DEFAULT_ON and BACKENDS_RESTORE_FAILED; an .so-less build without a receipt only records the default instead of false-reporting.
- Pipeline fixes: correct the single-variant test-package evidence download layout for dry-run/publish (bf491c77), so requesting only the debug test package no longer fails while merging evidence directories; restore the androidTest refreshPowerMode(Context) calls (872d48ac), which unblocks androidTest compilation in prebuilt debug builds.
