# DSHA 0.2.1-rc.5-20261115.1335-dsh0.2.2-rc.1 / build367

- APK 更新（M17）：更新確認はユーザーの操作で開始する方式に変更しました。起動時、アプリへ戻った時、ウィンドウのフォーカス取得時、更新ページを初めて開いた時には、自動確認やアップグレードの案内を行いません。ダウンロードと直列キューはアプリケーション単位の所有者が管理し、再生成されたページは元のタスクを監視します。権限とインストールの結果はユーザーの元の要求だけを継続し、失効したコールバックから新しい要求を作成せず、UNKNOWN の操作を再実行しません。
- 内蔵プラグインの有効化（T2）：インストール済みで管理対象の内容を厳密に証明できる内蔵プラグインが、第三者インポート規則を誤って適用され、有効化を拒否される問題を修正しました。既定の自動無効化マーカーとユーザーの意図を別々に記録します。ユーザーによる無効化と、由来不明の過去の空マーカーはアップグレード後も維持します。内蔵 dsh-web-mobile 3.3.5 のバージョンと既定で有効にする方針は変わりません。
- 起動復旧（S1a/S1b）：停止の事実を Kotlin でシャドー観測する仕組みと、純粋な引き継ぎ契約を追加しました。S1a は事実を記録するだけで、既存の停止判定を置き換えません。S1b は、無効化対象のプラグインが指定されていない保護付き復旧の限定された経路でのみ、引き継ぎ証明を一度だけ消費し、実行前に現在の識別情報と現場の状態を再確認します。引き継ぎに入る前に条件を満たさない場合は元の経路を使い、入った後の UNKNOWN、オブジェクト変更、許可失効は直接実行を阻止します。キャッシュミスとして再実行しません。通常起動と手動停止は元の経路を維持します。全経路の終了証明ではなく、PID やポートだけを根拠にプロセスを終了するものでもありません。
- バックアップのストリーム橋渡し（A3）：Rust の envelope ストリームを接続し、上限付きストリーム、失敗、後処理の契約を固定しました。既定のバックエンドは引き続き JVM で、Rust の利用には既存の有効化条件と利用可能条件の両方が必要です。Rust を選択したストリームが失敗しても、JVM に切り替えて読み直しや書き直しを行いません。v5 アーカイブ形式、完全性検証、復元の意味は変わりません。APK の off モードには Rust ライブラリを同梱しません。実際の Android Rust ストリームや電源断からの復旧について、端末受け入れ検証の完了は主張しません。
- Kotlin 移行：contract 領域全体の 18 ファイル、M17 の 4 ファイル、SAF の 15、ダウンロード／転送の 8、ネットワーク健全性の 3 Java ファイルを Kotlin に移行しました。実際の Java 呼び出し元と既存動作を領域ごとに確認しました。ABI 記録には可視性、final、コンパイラが追加したメンバーなどの境界を明記しています。contract の元の Java record 7 型は record メタデータを保持せず、ABI のビット単位の完全一致は主張しません。SAF「アプリ間ファイルアクセス」、ダウンロードキュー、復旧／公開、ネットワーク健全性の規則は既存の意味を維持し、Manifest 権限やデータ形式を新設しません。
