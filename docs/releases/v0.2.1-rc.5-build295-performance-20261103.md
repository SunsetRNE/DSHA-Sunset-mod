## 文件工具 SSE 错误

用户确认报错模型为 `gpt-6.1-sol`。真实随包 OpenAI SDK 7.19.0 的 ESM 和 CJS 解码器均可复现：只有 `event: ping`、没有 `data` 字段的控制块被错误产出，随后 `JSON.parse('')` 触发 `Error reading response: malformed server-sent event JSON`。两个精确补丁现在只跳过没有 data 字段的控制块，并释放这些控制块的诊断累积。

显式空 `data:`、损坏或截断 JSON 继续报错；完整 JSON 在 EOF、没有末尾空行及 `[DONE]` 的既有兼容性保留。新增 `DSHA_SSE_INVALID_JSON` 与 `dataChars` 诊断，不记录消息正文，不自动重发网络请求或重放已执行的文件工具。旧普通写入空 justification 兼容修复保留。

- 实际 SDK 回归 86 项通过，覆盖两种模块、切块、UTF-8、心跳、空数据和异常边界。
- 真实 PiAI Completions/Responses 调用链覆盖 HTTP、gzip、relay；真实沙箱写入 1008000 字节，再发出约 1.316 MB 的工具结果后续请求。候选 10/10 通过；旧解码器 10/10 符合预期缺陷对照。写入后下一响应损坏时，观察到两次请求、一次写入，无自动重放。
- 平板原 build205 与升级后的 build295 均实际调用 GPT-6.1-Sol 文件写入/读回；升级后新建 100 行含引号、反斜线和 Unicode 的文件并读回成功。
- DeepSeek-V4.1-Flash 实际创建/读回 20 行文件，读取已安装 SDK 补丁标记；最终 R2 又创建/读回 10 行新文件，只使用两次文件工具。

有限真实模型请求没有再次触发用户原始错误。本轮修复的是可稳定复现的实际 SDK 缺陷，不能证明它是用户接口全部间歇错误的唯一根因。没有抓取或公开外部提供方原始请求正文。模型对“无 data 字段”和“空 data 字段”的解释不作为实现证据，精确行为以 SDK 测试为准。
