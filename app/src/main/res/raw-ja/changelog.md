# DSHA 0.2.1-rc.5-20261111.0600-dsh0.2.2-rc.1 / build357

- 停止／再起動の意味づけを補完（T150、`5dde9205f`）：ホストが SIGTERM 後の終了を待つ予算を 3s から 6.5s に引き上げ、同梱 dsh 自身の 5s 強制終了上限を覆って余裕を残すため、正常終了が「未確認」と判定されなくなります。`PENDING_EXIT` は終端として早退せず、予算の尽きる時点でなお生存を検証できる場合だけ未確認とし、待機中にプロセスが消えたか番号が再利用された場合だけ記録を退役させます。待機中の同一性またはコマンドラインの変化は別途収束させ、以後いかなるシグナルも送らず、待機はメインスレッドを塞ぎません。
- 起動前の停止を同一ウィンドウで待機：起動フローは既知のランチャーに同じ優雅終了ウィンドウを与えた後、同一の 8s ウィンドウ内で読み取り専用の再確認を行います。旧インスタンスが終了中でも 10ms で「起動失敗：本アプリに未終了の Web があります」と報告しません。それでも失敗する場合は三要素（何が起きたか／影響／次の一手）で表示し、検証済みの残存 PID とマスクしたコマンド概要、および「起動」の再試行入口を示し、内部文字列だけを投げません。
- 復元確認に STOPPED_PENDING を追加（`core/WebSessionRecovery`、`core/WebSessionRestoreText`）：「ユーザーが停止した（停止センチネル）」を compatible の「バージョン非互換」から分離し、STOP_IN_PROGRESS / USER_STOPPED_EXIT_UNCONFIRMED の理由コードを新設しました。停止後にアプリを再起動しても「旧インスタンスのバージョン非互換／同一性を確認できない」と表示せず、INCOMPATIBLE / UNKNOWN にも落とさず、認証も旧インスタンスへの再接続も行いません。
