# DSHA 0.2.1-rc.5-20261114.1030-dsh0.2.2-rc.1 / build365

- 復元計画、移行の安全性、ターミナルのライフサイクルを修正するビルド：build365 は build364 の後に A3 slice2/3、RC1 の堅牢化、A4 のターミナルとプロセス識別、K1 のツール／ゲートおよび R3 の Rust gzip 別経路を統合します。A5/A7 のタスクベースラインとレビュー記録は文書であり、その後の実装スライスは本ビルドの対象外です。
- A3 slice2/3：復元プレビューは既存の計画を読み取り専用の PlanView v1 に投影します。送信時にはソースのダイジェストを再確認した後、現在時刻でビューを再生成し、検証を通過してから候補の構築とホストトランザクションのコミットに進みます。JVM 検証は有効で、Rust による第 2 実装はバックエンドが有効かつ利用可能な場合にのみ参加します。無効な計画、両実装の不一致、未検証の Rust 結果は送信を止め、原本とプライベートスロットを保持します。投影の対象外と明示されたケースは従来の JVM 復元経路を使用します。PlanView はアーカイブに保存せず、v5 データ形式と復元の意味論は変わりません。
- RC1 移行の堅牢化：実際の SettingsForms schema 参照グラフに従って秘密フィールドを投影し、入れ子と複合形状も扱います。不明な schema はディスパッチ前に拒否します。既存台帳の診断情報は秘密を除去し直し、秘密の値を新しい記録へコピーしません。設定全体の読み戻しは引き続き実際の update を検証します。`settings.update` のディスパッチ後に例外が起きた場合は `unknown` のままにし、エラーテキストを根拠に自動再試行しません。
- RC1 の履歴証拠：`expectedSections` がない旧台帳は、自身に残ったキーだけで完了を証明できません。代替 checkpoint には一致する ledger provenance が必要です。証拠の欠落、不正、矛盾は `unknown` のままです。そのため、build364 より前に完了し、後に build364 が再利用した一部の移行世代では、どちらの証拠源にも信頼できる証拠がなければ通常起動とセーフ起動の両方が阻止されます。原本と保持記録は読み取り専用で参照できます。本ビルドはこの保守的な阻止を維持し、迂回手段や自動再インポートは追加しません。
- Java↔CJS の起動引き継ぎ：キャッシュ済み履歴 prepare は許可前に今回の startup 識別情報と `history-only` モードをアトミックに書き込み、読み戻します。CJS は同一世代と同一入力の束縛を確認し、台帳の欠落や変更によって引き継ぎが新たな settings update に変わることを防ぎます。過去の業務レシートとユーザーが後で編集した値は保持します。バックアップ／データ形式は変わりません。
- A4 のターミナルとプロセス識別：guest の終了には空のセッションを 2 回観測する必要があり、自然終了経路でも二重スキャンを行います。識別情報を読めない場合、中断された場合、メンバーが残る場合は未確認状態を維持します。セッション ID はバックエンド起動前に予約し、永久に再利用しません。単一タブはそのセッションの終了を検証した後にのみ削除します。UID が不明なら別アプリと誤表示せず、識別情報を読み取れないと表示します。有限回のスキャンは任意の daemon に対するアトミックな終了証明にはなりません。
- A4 の受け入れツール：debug instrumentation は 30 個の旧 `targetPackage` 値だけを現在のアプリ識別情報に正確に置換し、旧ターミナルライフサイクルのフィクスチャを廃止します。現在の監査は再生成された Activity を観測し、自身が作成したタブだけを検証します。ホストの PTY ハンドシェイクテストは本番 C ソースを使用しますが、Android JNI、回転、言語切り替え、proot/proroot の実機受け入れが完了したことは示しません。
- K1/R3 のエンジニアリング：ツールとゲートはスキャン分類、コンストラクター／形状のアサーション、ネイティブテストの委譲、自己完結した契約を強化します。R3 は制限付きの単一メンバー gzip `archive_pack/unpack`、JVM ブリッジ、差分テストを追加します。Rust バックエンドは既定で無効で、`.so` は同梱せず、バックアップ envelope の呼び出し箇所への接続は A3 slice4 に残しています。ユーザーには見えない変更で、新しいユーザー設定は追加せず、アーカイブ形式も変えません。
- 上書き更新の影響：管理起動ソースが変わるため、`runtimeId` は **`8598a8dbf15d48773a41ff41e89935a9effcb5faaa0edc2b82f17dda223b5193`** です（起動入力 491、資産入力 205）。**364→365 の上書き後の初回起動では全画面の管理ランタイムメンテナンス画面に 1 回入り**、ランタイム試運転を実行します。個人データは保持されます。バージョン番号の引き上げ自体は runtimeId を変えません。同梱 `dsh-web-mobile` 3.3.5 と既定で有効な状態は変わりません。
- 固定ビルド入力：`fixed-inputs-20261113`、資産 `dsha-a-su-fixed-inputs-20261113-build364.zip` を再利用します（716,787,167 B、SHA-256 `2c8dc3fa494a5faf6f65cafa966b47d234a3331c30396198005cedfccca82cad`）。依存関係、基礎 Ubuntu、リカバリーアーカイブ、入力ロックの更新は含みません。管理ソースの検証は本ビルドを上記 descriptor に束縛し、ランタイムの recipe provenance はアーカイブのバイト列とは別に確認します。
