# DSHA 0.2.1-rc.5-20261106.0400-dsh0.2.2-rc.1 / build331

- proroot git large-diff crash becomes fail-loud (T82): with build330 (proroot v1.2.8), `git show --stat`, `git diff --stat` / `--numstat` deterministically crash for some commits or a single ≥8-path combination — exit 139, 0-byte stdout, and only `[proroot] SIGSEGV pc=… lr=…` on stderr. When such a command is piped to `| head` or chained with `;`, the final rc is swallowed as 0, so reviews or merges can silently receive empty data. The new shared wrapper `tools/git_guard.py` raises `GitSigsegvError` (`GIT_PROROOT_SIGSEGV`) as soon as rc=139 / -11 or the stderr marker is seen; it never retries, downgrades or returns partial output, and its message lists safe alternatives (`--name-status`, `--dirstat`, ≤7-path shards). Every repository tool that calls git now uses `git_output`, the new `tools/test-git-guard.py` is registered in the host-tests manifest, and AGENTS plus the runtime-engines docs record the local trap and safe review/merge usage.
