# DSHA 0.2.1-rc.5-20261106.0230-dsh0.2.2-rc.1 / build330

- Recusa iniciar o próprio host na tela virtual (T76): o `/app/vscreen/launch` não aceita mais o pacote do próprio DSHA como alvo. O sistema não cria uma instância separada para a tela secundária; ele reutiliza o mesmo processo em execução, e a WebView já vinculada ao display padrão cai com ponteiro nulo em `libmonochrome` na tela secundária (evidência do dispositivo relay: display 4, Looper da thread principal entrando na WebView, processo 14715 em execução reutilizado). O bridge recusa antes de qualquer pedido de autorização, o Manager antes do claim e o Core antes de enviar `am start`, todos pela mesma verificação, retornando `VSCREEN_SELF_LAUNCH_REFUSED` (`state=NOT_SENT`, nenhum comando de início é enviado e não há queda); o plugin embutido classifica esse código como pre-dispatch, o seletor nativo de aplicativos não lista mais o host e a página de resultado mostra o motivo em chinês/inglês. Esta é uma recusa de segurança, não suporte a self-launch em tela secundária; para suportar depois é preciso `createDisplayContext` com uma instância de WebView separada. O runtime descriptor é regenerado (runtimeId `6bea62f2`); as entradas fixas não são reconstruídas.
- Escopo de verificação: o grupo completo de contracts do host, a checagem de formatação de toda a árvore (JDK 17) e testes unitários direcionados (VirtualScreenPolicy, VirtualScreenManager ownership, página de atualização); não houve validação em dispositivo neste ambiente. Eleva o versionCode para 330 (base build329); a revisão do DSHA continua 0.2.1-rc.5 e o DSH embutido é 0.2.2-rc.1.
