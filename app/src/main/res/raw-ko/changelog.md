# DSHA 0.2.1-rc.5-20261111.0600-dsh0.2.2-rc.1 / build357

- 중지/재시작 의미 보완(T150, `5dde9205f`): 호스트가 SIGTERM 종료를 기다리는 예산을 3s에서 6.5s로 늘려 내장 dsh 자체의 5s 강제 종료 상한을 덮고 여유를 둡니다. 정상 종료가 더 이상 "확인되지 않음"으로 판정되지 않으며 `PENDING_EXIT`는 종료 상태로 조기 반환하지 않습니다. 예산이 끝날 때까지 생존을 검증할 수 있을 때만 미확인으로 보고하고, 대기 중 프로세스가 사라지거나 번호가 재사용될 때만 기록을 퇴역시킵니다. 대기 중 정체성이나 명령줄이 바뀌면 별도로 마무리하고 더는 어떤 시그널도 보내지 않으며, 대기는 메인 스레드를 막지 않습니다.
- 시작 전 중지 동일 창 대기: 시작 흐름은 알려진 런처에 같은 정상 종료 창을 준 뒤 동일한 8s 창 안에서 읽기 전용으로 재확인합니다. 이전 인스턴스가 종료 중일 때 더는 10ms 만에 "시작 실패: 이 앱에 아직 종료되지 않은 Web이 있습니다"라고 보고하지 않습니다. 그래도 실패하면 세 요소(무슨 일이 있었는지 / 영향 / 다음 단계)와 함께 검증된 잔여 PID, 마스킹된 명령 요약, "시작" 재시도 진입점을 보여 주고 내부 문자열만 던지지 않습니다.
- 복구 확인에 STOPPED_PENDING 추가(`core/WebSessionRecovery`, `core/WebSessionRestoreText`): "사용자가 중지함(중지 센티널)"을 compatible의 "버전 비호환"에서 분리하고 STOP_IN_PROGRESS / USER_STOPPED_EXIT_UNCONFIRMED 이유 코드를 새로 두었습니다. 중지 후 앱을 다시 시작해도 "이전 인스턴스 버전 비호환 / 정체성 확인 불가"를 표시하지 않고 INCOMPATIBLE / UNKNOWN으로 떨어지지 않으며, 인증하지 않고 이전 인스턴스에 다시 연결하지도 않습니다.
- 강제 중지 폴백: 증거가 부족할 때 더는 "중지 미완료"만 보여 주지 않고 검증된 PID / 명령 요약, 강제 중지할 수 없는 이유, 15초 후 재시도 진입점을 보여 줍니다. 레드라인은 그대로입니다 — 커널 출생 정체성이 검증된 PID에만 시그널을 보내고 이름 / 포트 / 맨 PID로 종료하지 않으며, 보안 경계와 프로토콜은 바꾸지 않습니다.
- 디바운스와 단계 보고(P1 E/F): 진행 중인 중복 중지는 같은 요청으로 합쳐져 단계 설명 한 번, 결론 콜백 한 번만 돌려주고, 강제 중지 후보는 15초에 최대 한 번만 준비합니다. 수동 중지는 상태 표시줄에 단계와 경과 초를 표시해 "중지 중…" 블랙홀을 설명 가능한 대기로 바꿉니다(`util/WebStopBudget`, `core/StartupStopWait`, `core/StartupStopText`, `core/WebForceStopText`, `ui/LaunchFragment`).
