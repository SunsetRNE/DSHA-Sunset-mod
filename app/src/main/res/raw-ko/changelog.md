# DSHA 0.2.1-rc.5-20261113.1340-dsh0.2.2-rc.1 / build364

- 데이터 안전성 및 시작 관측 빌드(사용자에게 보이는 데이터 정확성 수정 1건): build364는 build363 이후 RC1 마이그레이션 P1a/P1b와 비구현자 리뷰 P0/P1/P2 수정, K0 Kotlin 관리 입력 및 아키텍처 경계 게이트, S0 시작 읽기 전용 관측 기준선, 외부 adb/fastboot 경로와 최초 proroot 시험 실행 수정을 통합합니다. **사용자에게 보이는 것은 RC1 마이그레이션의 보수적 fail-closed 의미론**이며, K0 / S0는 빌드와 진단 인프라, 나머지는 기기 경로 수정과 문서입니다.
- RC1 마이그레이션(데이터 안전, 사용자 가시): 결과 프로토콜이 `resultVersion=3`으로 올라가 "이번 내용 복사본 재검증", "과거 완료", "쓰기 결과 알 수 없음"을 구분합니다. 이번 실행에서 복사본을 완전히 읽어 검증한 경우에만 마이그레이션 쓰기를 허용하고, 과거 완료는 마이그레이션 쓰기가 없는 일반 시작만 허용하며 committed 완료 영수증과 완전한 settings 원장을 요구합니다. 캐시 적중은 generation + sourceSha256 + 예상 섹션 집합에 묶이고 오래된 불리언으로 성공을 합성하지 않습니다.
- RC1 마이그레이션(계속): history-only 대조는 설정 섹션을 생성·갱신하지 않고 사용자가 나중에 바꾼 값을 덮어쓰지 않습니다. 원본 섹션이 없거나 pending/writing/unknown이면 pending/unknown을 반환하고 아무것도 쓰지 않습니다. 이미 전달되었지만 최종 상태를 모르는 쓰기는 자동 재생하지 않습니다. 보존 데이터 목록은 실제 current 형상에서 과거 완료 / 보류 / 알 수 없음을 투영하고, 알 수 없는 기록은 읽기 전용으로 볼 수 있으며 자동 복원·삭제 권한을 주지 않습니다.
- 시작 읽기 전용 관측(엔지니어링): S0는 중지 잔여물, 스캔, guest helper, 준비 적중, Node→인증 경로에 읽기 전용 카운트 관측을 추가하며 시작 진단과 기존 로그에만 반영합니다. 시작 순서·대기 시간·권한 게이트는 바꾸지 않습니다.
- Kotlin 관리 입력(엔지니어링): K0는 관리 소스 트리의 `.kt`를 `runtimeId`와 아키텍처 경계 게이트에 포함하고 Kotlin 컴파일/포맷 및 중복 키 부정 통제를 추가합니다. 실행 동작은 바뀌지 않습니다.
- 기기 경로 및 유지보수 시험 실행 수정: 외부 기기 라이브러리 검색에 `usr/lib/aarch64-linux-gnu/android`를 추가해 외부 환경에서 adb / fastboot를 찾을 수 있습니다. 최초 proroot 관리 런타임 시험 실행은 profile 열거 ENOENT로 더 이상 충돌하지 않아 유지보수 화면에서 실패 시험이 한 번 더 실행되지 않습니다.
- 문서 및 인수(문서만): build363 실기기 덮어쓰기 인수 영수증, 런타임 trial 최초 실패 분석, RC1 마이그레이션 설계와 대외 답변, 시작 체인 평가를 문서 색인에 넣습니다.
