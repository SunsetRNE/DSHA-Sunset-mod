# DSHA 0.2.1-rc.5-20261112.1800-dsh0.2.2-rc.1 / build360

- 릴리스 엔지니어링 유지보수 빌드(G0): build359 이후 `main`에는 Rebirth 발행 신원 정비, 모듈화 라인 문서, CI 변형만 포함되며 **앱 소스 / 리소스 / 문구 변경은 없습니다**. build360의 사용자 가시 동작은 build359와 완전히 같고, 업그레이드는 빌드 신원과 릴리스 엔지니어링만 바꿉니다.
- Rebirth 격리 실험 라인 정비: 전용 `dsh.android.client.rebirth` 신원 파일, `-Pdsha.rebirthCandidate=true` 미서명 후보 스위치, 독립 `signingConfigs.rebirth`(`DSHA_REBIRTH_*`만 읽고 정식 키로 폴백하지 않음), 후보 검증기를 추가했습니다. 인증서는 아직 없으므로 `UNSIGNED_NOT_FOR_INSTALLATION` 후보만 생산하며 서명 / 설치 / 릴리스 수용은 하지 않습니다. 첫 후보(CI run 43188205334)는 신원 / 매니페스트 / 미서명 12개 검사를 모두 PASS했습니다.
- 모듈화 라인 문서: 수렴표 v0.2, A1 계약 초안(C01/C02 + 결과 5필드 + 투영표), ADR-0004 결정 8과 G0–G5 게이트 상태를 동기화했습니다. 문서만 변경하며 런타임 동작은 바뀌지 않습니다.
- 관리 런타임 불변: 이번 변경은 `runtime-descriptor`의 `launcherInputs`에 없으므로 `runtimeId`는 **`4d55973d`**(205개 입력) 그대로입니다. **359→360 덮어쓰기 업그레이드는 런타임 유지보수 페이지로 들어가지 않습니다.** fixed-inputs는 `fixed-inputs-20261105e`로 고정되며 내장 `dsh-web-mobile` 3.3.5와 기본 활성화도 그대로입니다.
- 버전과 범위: versionCode를 360으로 올립니다(공개된 build359 / `73890983` 기준). DSHA 리비전은 `0.2.1-rc.5`, 내장 DSH는 `0.2.2-rc.1`입니다. build359는 이미 공개되었고(tag `dsha-a-su-build359-20261111-120000` @ `73890983`), 목표 tag `dsha-a-su-build360-20261112-180000`은 사용자 확인 후 release 워크플로가 만듭니다.
- **미검증 / 미수용**: build360은 단위 테스트, lint, 저장소 게이트만 통과했습니다. 앱 동작 변화는 없지만 실기기 덮어쓰기 수용 테스트는 아직입니다. G0 게이트는 미통과(Rebirth 인증서 없음, 서명된 후보 없음, 실기기 설치 / 동일 라인 덮어쓰기 증거 없음). `.debug` / `.dev` 패키지만 허용하며 본 기기에 정식 패키지를 설치하지 않고 정식 데이터도 건드리지 않습니다.
