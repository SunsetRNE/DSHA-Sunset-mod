# DSHA 0.2.1-rc.5-20261111.0600-dsh0.2.2-rc.1 / build357

- Завершение семантики остановки/перезапуска (T150, `5dde9205f`): бюджет ожидания выхода по SIGTERM у хоста поднят с 3 с до 6,5 с, что покрывает собственный 5-секундный предел принудительного выхода встроенного dsh с запасом, поэтому штатное закрытие больше не считается «неподтверждённым»; `PENDING_EXIT` больше не является терминальным досрочным выходом, неподтверждённым он становится только если к концу бюджета процесс всё ещё можно проверить, запись снимается только когда процесс исчез или его номер переиспользован, а изменение идентичности или командной строки во время ожидания обрабатывается отдельно и сигналы больше не посылаются; ожидание не блокирует главный поток.
- Остановка перед запуском ждёт в том же окне: поток запуска сначала даёт известному лаунчеру такое же окно штатного выхода, затем в течение одного 8-секундного окна перепроверяет только чтением; старый экземпляр, который ещё выходит, больше не приводит к ошибке через 10 мс «запуск не удался: в приложении ещё есть не завершившийся Web». Если ошибка осталась, экран показывает объяснение из трёх частей (что произошло / влияние / следующий шаг) с проверенным остаточным PID, маскированной сводкой команды и входом «Запуск» для повтора, а не голую внутреннюю строку.
- Восстановление добавляет STOPPED_PENDING (`core/WebSessionRecovery`, `core/WebSessionRestoreText`): «пользователь остановил (стоп-сентинел)» отделён от совместимого «версия несовместима», добавлены коды причин STOP_IN_PROGRESS / USER_STOPPED_EXIT_UNCONFIRMED; после остановки перезапуск больше не показывает «версия старого экземпляра несовместима / идентичность не подтверждена», не попадает в INCOMPATIBLE / UNKNOWN, не выполняет аутентификацию и не переподключается к старому экземпляру.
- Деградация принудительной остановки: при недостатке доказательств интерфейс больше не ограничивается «остановка не завершена», а показывает проверенный PID / сводку команды, причину невозможности принудительной остановки и вход повтора через 15 с; красная линия неизменна — сигнал получает только PID, чья идентичность рождения в ядре проверена, никогда по имени / порту / голому PID, границы безопасности и протокол не меняются.
- Дебаунс и отчёт о фазах (P1 E/F): повторная остановка во время выполнения сливается в один запрос (одна строка фазы, один колбэк результата), кандидат принудительной остановки готовится не чаще раза в 15 с, а ручная остановка показывает в строке состояния фазу и прошедшие секунды, превращая «чёрную дыру» «остановка…» в объяснимое ожидание (`util/WebStopBudget`, `core/StartupStopWait`, `core/StartupStopText`, `core/WebForceStopText`, `ui/LaunchFragment`).
- Последующие правки ворот после T150 (`bedaa5deb`): HarnessController возвращается к пределу фасада в 300 строк (удалён избыточный псевдоним getProot(), а семь мест вызова в HttpShellService переведены на proot()); кнопка «Перепроверить» в диалоге неудачной принудительной остановки LaunchFragment повторно использует существующий текст «Повторить» / Retry вместо новой языковой клавиши; управляемый descriptor пересчитан, поэтому `runtimeId` build357 — **`c780bc22`** (205 входов, заменяя `25235b80` из отдельного T150).
